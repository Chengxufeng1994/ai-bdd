# Actor

**更新於**: 2026-08-19

各份 example map 的 Story 句子回指這裡的角色名，不重複定義。
一個人可以同時是多個角色。

## 重訓者

**是誰**: 進健身房做重量訓練、想把每次訓練記下來並看出自己有沒有進步的人

**怎麼取得**: **沒問過**。需求裡沒有一個字提到註冊、登入或帳號。但兩件事隱含
資料綁在某個人身上：「動作庫要讓使用者自己新增」與「跟前一週比較」。
`custom-exercise-library/questions/custom-exercise-visibility.md` 答成「私有」
之後，資料以人為界就定了——但**怎麼成為一個人仍然沒問**。

**跟誰不同**: 範圍內沒有第二個人類角色。這不是漏列，是這份需求真的只有一種人
在用——見下方「不是角色的東西」，那張表是這一格的證明。

**能做什麼**

| 能力 | 來源 |
| --- | --- |
| 開始／結束一次訓練 | `log-a-workout` Rule 1、Rule 2 |
| 記錄動作、組、重量、次數 | `log-a-workout` Rule 3 |
| 標記某一組為熱身 | `log-a-workout` Rule 4 |
| 看到這次訓練的總容量 | `session-training-volume` Rule 1 |
| 設定體重與顯示單位 | `session-training-volume` Rule 6、`Shared 3` |
| 修改／刪除已記錄的訓練 | `edit-a-logged-workout` Rule 1、Rule 3 |
| 翻閱歷史紀錄 | `workout-history` Rule 1 |
| 看本週與上週同期的比較 | `week-over-week-progress` Rule 2 |
| 新增／改名／封存自己的自訂動作 | `custom-exercise-library` Rule 1、Rule 4、Rule 5 |

## 不是角色的東西

列出來是因為否則下一輪會有人再提一次。

| 考慮過 | 為什麼不是 | |
| --- | --- | --- |
| **系統** | 找過了：沒有任何一條規則的主詞是系統。關鍵在 `log-a-workout` Rule 2——訓練**不會**逾時自動結束，是使用者明確按結束。若當初答成「30 分鐘沒動作自動結束」，系統立刻就是一個真的 actor，還會長出一整組沒人問過的規則 | `log-a-workout/questions/session-boundary.md` |
| **教練** | 需求沒有任何一條規則提到「別人看我的紀錄」。硬加會立刻長出「誰能看誰」的權限矩陣，而那幾十格沒有一格有來源 | 有需要時再開問題卡 |
| **未登入的訪客** | 這是最常被漏的一種，所以特地找過。但需求沒有任何「不登入也能做什麼」的敘述 | 併入「怎麼取得」那格未問的卡 |
| **內建動作庫的維護者** | 它確實存在（`duplicate-exercise-name` 的規則要拿內建動作比對），但它**從不是任何一條規則的主詞**——規則約束的是「動作」這個物件。合併測試：把它跟重訓者合併，沒有任何一條規則會變錯 | `custom-exercise-library/questions/built-in-library-source.md`（待答） |
| **健身房** | 出現在需求敘述裡（「同一台器材在不同健身房叫法不一樣」），但那是**動機**不是角色。沒有規則以健身房為主詞 | |
