## 規則

### Rule 1. 已結束的訓練可以修改任何欄位，沒有時間限制
- Example 1.1 8/12（一週前）的臥推某組從 60 kg×8 改成 70 kg×8 → 接受
- Example 1.2 在 8/12 的訓練裡補一個 8/12 當天忘記記的動作 → 接受
- Example 1.3 把 8/12 某組改標為熱身 → 接受

### Rule 2. 所有彙總以當前資料重算，不保留快照
- Example 2.1 8/12 原本總容量 1520，把某組從 60×8 改成 70×8 → 8/12 總容量變成 1600
- Example 2.2 承上，8/12 所在那一週的總容量同步變成 1600
- Example 2.3 把 60×10 那組改標為熱身 → 總容量從 1520 降為 920，明細裡仍看得到那一組

### Rule 3. 刪除訓練不可復原，且刪除前要看得到這筆的摘要
- Example 3.1 對 8/12 的訓練要求刪除 → 先看到摘要「2026-08-12，1 個動作、3 組、總容量 1520」，此時訓練還在
- Example 3.2 刪除後 → 該筆從歷史消失，8/12 當日與該週的總容量都變成 0，沒有垃圾桶可復原

## 備註
- **切分依據**：從 `log-a-workout` 切出來的。理由是它可以晚一個版本交付——
  第一版只能記不能改仍然可用（需求說使用者現在用紙本，紙本也不好改）。
  切出來之後 `log-a-workout` 從 10 條規則降到 9 條，且少掉唯一一條會回頭改動
  歷史資料的規則。
- **Rule 3 的措辭是刻意改過的**：原本寫成「刪除必須經過二次確認」，那會逼出
  一個「要求刪除 → 確認／取消」的三步流程，而「取消」在伺服器上什麼都不做——
  用它寫出來的驗收條件**在刪除功能整段拿掉時照樣會通過**。改成約束結果
  （不可復原、刪除前看得到摘要）之後，兩個例子都驗得到東西。確認對話框仍然要做，
  但那是介面的事，不是這裡的驗收條件。
- **重複面向標 `—`**：兩個裝置同時編輯同一筆是真實會發生的，但要先知道有沒有
  多裝置同步。那要等 `actor.md` 裡「怎麼成為使用者」那一格被填上才問得動。
  之所以仍判定就緒：單裝置下這 3 條規則是完整的，多裝置會**新增**規則而不會
  推翻現有的。
- **被推翻的提案**：我原本傾向軟刪除加 30 天垃圾桶。否決的理由是那會讓每一個查詢
  都要記得過濾已刪除的資料——漏掉一處就是總容量默默算錯，而那種 bug 使用者不會
  回報，因為他無從發現。
