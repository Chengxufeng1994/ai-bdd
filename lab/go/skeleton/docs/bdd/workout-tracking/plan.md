**seam**: `interfaces/http` 的 router，由 `bootstrap.NewHandler` 組出，
`httptest` in-process 打 HTTP、不經過真實 socket——沿用

## 前置整理（prefactoring）

沒有——現有結構（`bootstrap.Deps`、`port/in`／`port/out`、`application/service`、
`application/usecase/{command,query}`、`interfaces/http` 的 mapper／presenter／
errmap 三段式、`application/errors.Error` 的 Kind／MessageKey 分類）就是這六則
story 要延伸的地方，沒有東西需要在票 01 之前先重構。

唯一值得記下但不構成前置整理的一點：`application/errors/errors.go` 的套件註解
明講「沒有錯誤目錄，因為現在只有一個 `MessageKey`」，並自陳「第二個字面
`MessageKey` 出現時這個假設就不再成立」。02 一張票就會一次引入十幾個
`MessageKey`（必要參數未提供、單一動作最多 20 組……），率先踩線；要不要順手建
目錄留給 02 自己決定，不在這裡替它做決定。

## 票

依賴序排列，blockers 在前。編號一旦寫出去就不重排——`bdd-implement 03` 靠它定位。

九張票的順序：01（開始）→ 02（記錄）→ 03（結束＋基本容量）→ 04（六型別容量）；
05（歷史，橫向拉出 03 之後）→ 06（編輯，橫向拉出 05 之後）；07（週對照，硬依賴
03，軟依賴 04）；08（自訂動作 CRUD，與 01 平行）→ 09（封存／改名／型別保護）。

### 01 — 開始一次訓練

**交付什麼行為**：使用者在沒有進行中訓練時可以按下開始，立刻建立一筆進行中的
訓練並讀回它的開始時間；已經有一筆進行中的訓練時再按開始會被擋下，並看到那筆
還沒結束的訓練仍是原來的樣子。

**涵蓋場景**：
- log-a-workout：`@example-1.1`、`@example-1.2`

**Blocked by**：無，可立即開始

**內迴圈**：歸屬日換算（時區 → Date，只求值不對外斷言）、進行中訓練的唯一性
檢查

- [ ] 沒有進行中訓練時 `POST /workouts` 建立一筆進行中的訓練，`GET
      /workouts/{workoutId}` 讀回開始時間為 `2026-08-19 19:12`（Example 1.1）
- [ ] 已有一筆 `2026-08-18 19:12` 開始、尚未結束的訓練時再次 `POST /workouts`
      回操作失敗，錯誤訊息為「已有進行中的訓練」，且原本那筆的開始時間仍讀回
      `2026-08-18 19:12`（沒有被覆蓋）（Example 1.2）

### 02 — 記錄動作與組

**交付什麼行為**：使用者可以在一筆進行中的訓練裡記下一組又一組（含自體重型
動作不需要填重量），並把完整、依序的組清單讀回來；重量或次數超出範圍或精度、
缺少必要的次數、單一動作或單次訓練超過上限，都會被擋下並看到訊息；同一個
動作再次出現時記成獨立的區塊而不與前一次合併。**這張票不碰任何容量公式**——
組裡出現的少數幾個「總容量」斷言（Example 3.1／3.2／3.3、8.1–8.4）都是單一
負重型、無熱身的最簡單情形（重量直接相乘次數），不涉及熱身排除或
`effectiveWeight` 的任何分支；那兩塊分別是 03 與 04 才要建立的能力。

**涵蓋場景**：
- log-a-workout：`@example-2.1`、`@example-2.2`、`@example-3.1`、
  `@example-3.2`、`@example-3.3`、`@example-3.4`、`@example-5.1`、
  `@example-8.1`、`@example-8.2`、`@example-8.3`、`@example-8.4`、
  `@example-8.5`、`@example-8.6`

**Blocked by**：01（要先有一筆進行中的訓練才能記組）

**內迴圈**：契約層擋下缺少次數、單組基本乘法（weight × reps，含 reps=0，無
熱身排除、無 effectiveWeight 分支）、自體重型的重量欄可省略（不求
effectiveWeight——這個場景本身不斷言總容量）、精度與值域驗證、組數上限
（20）、相異動作數上限（50）、相鄰動作折疊（Rule 5）、歸屬日不隨當下時間
改變

- [ ] 進行中訓練隔天（`2026-08-20 09:00`）仍可 `POST .../sets` 記一組
      60kg×8，操作成功，訓練狀態仍讀回「進行中」、歸屬日仍讀回
      `2026-08-19`；放置五天的進行中訓練同樣可以記組且狀態仍為「進行中」
      （Example 2.1、2.2）
- [ ] 缺少次數時 `POST .../sets` 回操作失敗，錯誤訊息「必要參數未提供」，
      訓練總容量維持 0（Example 3.2）
- [ ] 提供次數 8／0 時該組成立，操作成功後總容量分別讀回 480／0（Example
      3.1、3.3）
- [ ] 自體重型動作不帶重量、只填次數 20 時該組仍成立，讀回的組清單只有次數
      20、重量欄空白（Example 3.4）
- [ ] 重量 62.5（小數點後一位）被接受，總容量讀回 500；重量 1000.5（超上限）
      與 62.55（超精度）都回操作失敗，總容量維持 0（Example 8.1、8.2、8.3）
- [ ] 次數 101 回操作失敗，總容量維持 0（Example 8.4）
- [ ] 單一動作已有 20 組時再記第 21 組回操作失敗，錯誤訊息「單一動作最多 20
      組」（Example 8.5）
- [ ] 單次訓練已有 50 個動作時再記第 51 個動作回操作失敗，錯誤訊息「單次
      訓練最多 50 個動作」（Example 8.6）
- [ ] 已有臥推 1 組（60×8）、划船 1 組（50×10）的訓練裡再記一組臥推
      （55×8），讀回的「動作區塊」依序是臥推(1 組)、划船(1 組)、臥推(1 組)
      三個獨立區塊，不與前一次臥推合併；總容量讀回 1420（Example 5.1）

### 03 — 結束訓練與基本總容量

**交付什麼行為**：使用者結束一筆訓練時看到總容量已經排除熱身組；力竭後降

不因為跨午夜才結束、或事後換了時區而改變。

**涵蓋場景**：
- log-a-workout：`@example-4.1`、`@example-4.2`、`@example-6.1`、
  `@example-6.2`、`@example-9.1`

也預期訓練裡已經有組）

**內迴圈**：容量公式（排除熱身，含全部熱身時為零的邊界）、dropset 記成兩個
獨立組後正確加總、`Complete` 不改變已經凍結的 `attributedDate`、換時區後查詢
仍讀到原本的歸屬日

- [ ] 深蹲 4 組（20×10 熱身、40×10 熱身、80×8、80×8）記錄後，讀回的組清單

- [ ] 一個動作的組全部標為熱身時，該動作對總容量的貢獻讀回 0（Example 4.2）
- [ ] `2026-08-19 23:40` 開始、`2026-08-20 00:50` 結束的訓練呼叫

### 06 — 編輯與刪除已記錄的訓練

**交付什麼行為**：使用者可以修改已結束訓練的任何一組（改數值、補記漏掉的
動作、改標熱身），所有彙總（該次總容量、該週總容量）都以修改後的資料重算；
使用者可以在刪除前看到這筆訓練的摘要，刪除後這筆從歷史與週彙總都消失，且
無法復原；歷史清單顯示的總容量在有人修改過後，讀到的是查詢當下重算出來的
值，不是記錄當時的快照。

**涵蓋場景**：
- edit-a-logged-workout：`@example-1.1`、`@example-1.2`、`@example-1.3`、
  `@example-2.1`、`@example-2.2`、`@example-2.3`、`@example-3.1`、
  `@example-3.2`
- workout-history：`@example-6.1`

## 缺口

`spec.md` 沒定案、但切票時發現需要的。不是票——不是可執行的行為；不是前置
整理——不是現在就能做的改動。

- **`ExerciseUsage` 沒有對應的埠。** `spec.md` 的 Implementation Decisions
  把 `ExerciseUsage` 列為跨聚合的 domain service（「這個動作有沒有被任何
  `workout_set` 引用」），但只具體給了兩個讀取埠的簽章（`WorkoutHistoryView`、
  `WeeklyVolumeView`），沒有第三個「依 exercise ID 查使用次數／是否被引用」
  的埠或方法簽章。09（custom Rule 4／5／6）需要它才能做刪除前檢查、改型別
  前檢查。留給 IMPLEMENT 補一個埠（例如 `out.ExerciseUsageQuery`），或決定
  `WorkoutRepository` 順便長出這個查詢方法。
- **「當日／週總容量」的觀察路徑沒有拍板。** `spec.md` 把它列在「留給
  IMPLEMENT」：建議用 `GET /workouts` 逐筆加總，不新增端點。05 的 log
  Rule 7（`@example-7.1`）與 06 對 05 的 Blocked by 都建立在這個建議之上——
  如果 IMPLEMENT 階段選了別的觀察路徑（例如直接讀 `WeeklyVolumeView`），
  05／06 這兩張票裡跟「當日總容量」有關的驗收條件要重新對照新路徑重寫，但
  票的邊界本身不受影響。
