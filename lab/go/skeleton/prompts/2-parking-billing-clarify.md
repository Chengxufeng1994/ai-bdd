# CLARIFY 的固定測試提示 — 停車場計費（口語 brief 版）

第二個評估情境。與[健身追蹤](./1-fitness-tracker-clarify.md)測的不完全一樣：

| 情境 | 主要測什麼 |
| --- | --- |
| 健身追蹤 | 需求裡**沒提到的東西**（自體重、單邊動作）問不問得出來 |
| **本檔（停車場）** | 需求裡**寫得像已經定案的數字**，敢不敢當成未定案來問 |

兩者互補。前者測「看不見的洞」，後者測「看起來已經填好的洞」。

模糊點與及格標準定義在本檔。每次評估用同一段輸入，**逐字複製，不要即興改寫**。

---

## 輸入

```
# 社區地下停車場計費系統

我們要幫社區的地下停車場做一個計費系統。

住戶有月租車位，訪客臨時停車要收費。

費率大概是前 30 分鐘免費，之後每小時 30 元，一天最多收 300。

月租戶開進來不用收錢。訪客離場的時候在繳費機付款，付完才能出去。

管委會希望能看到每個月的收入報表。
```

---

## 為什麼是這樣措辭

| 特性 | 理由 |
| --- | --- |
| **費率寫成三個具體數字** | 這是本情境的核心。「前 30 分鐘免費，之後每小時 30 元，一天最多收 300」讀起來像三個已知條件，實際上是**三條各自缺一個判斷的規則**。健身追蹤的模糊點是「沒寫」，這裡的模糊點是「寫了，但寫的是結果不是規則」 |
| 「大概是」 | 唯一的軟化詞，而且只有一個。它是唯一的明示線索——**沒抓到這個詞的執行，後面多半也不會質疑那三個數字** |
| 完全不提硬體 | 「訪客離場的時候在繳費機付款」暗示有繳費機，但沒說訪客怎麼進場、系統怎麼認出月租車。這決定計時起點，也決定好幾則 story 的邊界 |
| 完全不提車種 | 機車？大型車？需求從頭到尾只有「車」一個字，隱含只有一種車輛型別而沒說 |
| 「月租戶開進來不用收錢」 | 只講了正常路徑。卡片壞了、忘記帶卡、資格已終止但卡沒收回——全部沒提 |
| 「付完才能出去」 | 讀起來是一句完整的規則，實際上少了時限。付完之後在場內待兩小時再出去呢 |
| 需求方是管委會，不是使用者 | 紅卡該問誰因此變成真問題（管委會？住戶？設備商？）——有些題目管委會根本答不出來 |

---

## 模糊點

分三層，因為**它們被發現的時機不同**，而那正是這份 eval 最有診斷力的地方。

### 第一層 — Pass 1 就該問（答案改變切分方式）

1. 月租費帳務在不在這個系統範圍內
2. 系統怎麼認出月租車與訪客車（硬體機制）
3. 月租名單的建立與異動在不在範圍內
4. 報表包含哪些收入
5. 車位容量要不要管

### 第二層 — Pass 2 深度追問

6. **不滿一小時的零頭怎麼算**（進位／捨去／按分鐘）
7. **「一天」是自然日還是進場起算 24 小時**
8. 剛好停滿 30 分鐘算不算免費
9. 付款完成到出場的時限
10. 票券遺失或出口讀不到
11. 短時間重複進出（免費時段被重複利用）
12. 繳費機或系統整台故障時的降級行為
13. 跨自然日停留，出場收幾次錢、報表怎麼歸屬
14. 月租卡讀不到／忘記帶卡
15. 資格已終止但卡片還沒收回
16. 當月零筆交易時報表長什麼樣
17. 重複付款訊息會不會讓報表虛增
18. 車輛型別是不是只有一種

### 第三層 — 只有推導才會浮現

19. **政策與硬體的矛盾**：「要堵重複進出的漏洞」需要認出同一輛車，但「沒有車牌辨識」已經定案。這一條不會在提問時出現，只會在**抽規則時**撞出來
20. **完全沒付錢的人走到出口**：第 9、10 項都答完之後仍然缺這一格。實測中它是 **SPEC 寫場景時才發現的**，不是 CLARIFY 問出來的

---

## 及格標準

**必要（沒問到就算失敗）**：第 6 與第 7 項。

理由：它們是唯二**金額差好幾倍**的規則，而且都藏在讀起來像已定案的句子裡。第 7 項的差異最大——停三天付 300 還是 900。一個沒問這兩題的執行，等於把「大概是」三個字整段跳過。

**進階（區分「夠用」與「好」）**：第 19 項。

抽規則時撞出矛盾之後，執行有沒有**停下來開一個新問題**，而不是自己挑一個變通做法往下走。這一條測的不是提問能力，是**誠實**。

**鏈的完整性**：第 20 項。

它衡量的是 CLARIFY 有沒有真的做完。實測中 CLARIFY 沒抓到、SPEC 抓到了——那不是 SPEC 的功勞，是 CLARIFY 的漏。若某次執行在 CLARIFY 就問到它，那次比實測基準好。

---

## 怎麼比較兩次執行

| 觀察項 | 好的樣子 |
| --- | --- |
| 「大概是」 | 有沒有被當成訊號。三個數字有沒有被當成待確認而非已知 |
| 分層 | Pass 1 只問改變切分的題，沒有一開始就追費率細節 |
| 硬體 | 有沒有發現「怎麼認出月租車」沒被回答，而且它決定計時起點 |
| 矛盾 | 抽規則撞到矛盾時，記成新問題還是自己和稀泥 |
| `n/a` | 標不適用的有沒有寫理由，還是空著 |
| 追問覆蓋 | 十一個業務面向掃過幾個，`—` 有沒有誠實留著 |
| 就緒判定 | 有未答問題時有沒有擋住不進 SPEC |
| 推翻 | 前一輪的答案被後來的發現推翻時，有沒有留下推翻的理由與原話 |

## 實測基準（2026-09-03，重切後第一次）

供對照，不是目標：CLARIFY 三輪問答收斂，24 已答／17 `n/a`／0 待答，
十一個業務面向與五個技術面向全數覆蓋，三則 story 全部就緒。
第 6、7、19 項都問到了；**第 20 項漏掉，由 SPEC 補抓**。
