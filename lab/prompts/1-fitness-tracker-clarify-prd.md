# CLARIFY 的固定測試提示 — PRD 版

與 [`1-fitness-tracker-clarify.md`](./1-fitness-tracker-clarify.md) 同一個情境、
同一批模糊點，但輸入寫成**已核准的 PRD**。

兩份分別測不同的失敗模式：

| 版本 | 測什麼 |
| --- | --- |
| 口語 brief | 面對明顯不完整的輸入，能不能問出該問的 |
| **PRD** | **面對看起來已經完成的輸入，敢不敢質疑它** |

**逐字複製，不要即興改寫。**

---

```
# PRD：訓練追蹤 App v1.0

**狀態**：已核准
**版本**：1.0
**負責人**：產品部

## 1. 背景

重訓族群目前多以試算表或紙本記錄訓練，練後需自行按計算機加總訓練量，流程
繁瑣且容易漏記。使用者訪談顯示，多數受訪者曾因記錄麻煩而中斷追蹤。

## 2. 目標

提供重訓者低摩擦的訓練記錄工具，並自動計算訓練量，使其能持續追蹤進步狀況。

## 3. 目標使用者

有規律重訓習慣（每週三次以上）、目前使用試算表或紙本記錄的族群。

## 4. 功能需求

| 編號 | 需求 | 優先級 |
|------|------|--------|
| FR-1 | 使用者可建立一次訓練，並在其中新增多個動作 | P0 |
| FR-2 | 每個動作可新增多組，每組記錄重量與次數 | P0 |
| FR-3 | 系統應計算並顯示本次訓練的總容量，公式為 Σ(重量 × 次數) | P0 |
| FR-4 | 使用者可查看歷史訓練紀錄，依日期排序 | P1 |
| FR-5 | 使用者可將本次訓練與前一週的同一動作進行比較 | P1 |
| FR-6 | 使用者可自行新增動作至動作庫 | P1 |

## 5. 非功能需求

| 編號 | 需求 |
|------|------|
| NFR-1 | 記錄一組的操作應在三秒內完成 |
| NFR-2 | 無網路環境下仍可記錄 |

## 6. 不在本次範圍

- 課表規劃與訓練計畫產生
- 社群功能（追蹤、分享、排行榜）
- 穿戴裝置整合
- 營養與體重管理

## 7. 成功指標

- 上線三個月內週活躍使用者達 5,000
- 使用者平均每週記錄 2.5 次訓練
- 三十日留存率高於 40%

## 8. 假設

- 使用者已知自己要做什麼動作，App 不需提供動作教學
- 單一使用者、單一裝置，本期不支援多裝置同步
```

---

## 這一版多了哪些陷阱

口語版的陷阱（「每組多重、做幾下」隱含每組都有重量）在這裡以 `FR-2` 保留。
以下是 PRD 這個**形式**額外帶來的：

| 陷阱 | 為什麼有效 |
| --- | --- |
| **`FR-3` 直接給了公式** | 看起來把規則定死了。但公式定義的是**算法**，不是**輸入**——它沒說哪些組算數、沒有重量的組怎麼辦。接受它就等於跳過整個 story 的核心 |
| **「狀態：已核准」** | 權威訊號。測 skill 會不會因為文件看起來定案就降低追問強度 |
| **編號與優先級** | `P0`／`FR-3` 讓每一條看起來都是決定過的。實際上 `FR-3` 一個字都沒定義「組」 |
| **`FR-5` 的「前一週的同一動作」** | 兩個未定義詞裝成已定義：「前一週」怎麼算？「同一動作」怎麼判定相同？ |
| **第 6 節「不在範圍」** | 製造範圍已收斂的錯覺。它排除的都是不相干的東西，真正的邊界一條都沒提 |
| **第 7 節成功指標** | 全是參與度指標（週活、留存），沒有一條衡量「使用者是否真的判斷得出進步」——目標與指標脫節，但看起來很完整 |
| **第 8 節「假設」** | 只列了兩條無關痛癢的，把承重的假設（一組是什麼、單位、哪些組計入）全部略過。**一份標明了假設的文件，反而讓人不去找沒被標明的那些** |

## 沒有變的部分

**十個模糊點一個都沒寫進去**：自體重、單邊、熱身組、失敗組、dropset、單位、
器材、等長動作、總容量的範圍。及格標準與觀察項完全沿用口語版，見
[`1-fitness-tracker-clarify.md`](./1-fitness-tracker-clarify.md)。

## 額外的觀察項

跑 PRD 版時，除了那十項再多看三個：

| 觀察項 | 好的樣子 |
| --- | --- |
| 對 `FR-3` 的態度 | 有沒有指出「公式沒有定義哪些組計入」，而不是把它當成已解決的 Rule |
| 對第 8 節的態度 | 有沒有發現承重的假設不在假設清單裡 |
| 對第 7 節的態度 | 有沒有問「這些指標衡量的是使用量，不是這個 story 的目的」 |

三項都沒發生，代表 skill 被文件的形式說服了——**那比在口語版漏問模糊點更嚴重**，
因為真實世界的需求多半以這種形式抵達。
