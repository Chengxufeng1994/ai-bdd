# 怎麼定義 Actor

`docs/bdd/actor.md` 的寫法。讀這份的時機：步驟 1，第一次識別角色，
或後面某一輪冒出一個沒見過的角色。

Actor 是**角色**，不是帳號。「Alice」是實例，「已購買旅程的學員」才是角色，
而同一個人可以同時是好幾個角色。

---

## 每個角色三件事

| 欄位 | 內容 | 為什麼必填 |
| --- | --- | --- |
| **是誰** | 一句話，用業務語言 | 沒有這句，角色名稱會被各自解讀 |
| **怎麼取得** | 具體條件 ＋ 來源 | **最常漏的一格**，見下 |
| **跟誰不同** | 區分它的那條規則 ＋ 來源 | 沒有區分的兩個角色是同一個角色 |

再加一欄 **能做什麼**：從已抽出的規則列，每一條回指來源。
這一欄在澄清進行中會一直長，那是正常的。

## 「怎麼取得」是最常漏的一格

規格會說「老師可以編輯課程」，但**不會說怎麼變成老師**。

那不是疏忽，是視角問題：寫規格的人心裡已經有一個老師，所以不會問他哪來的。
而實作的人一定會撞到——建立老師的入口在哪？誰能授予？可以撤銷嗎？

```markdown
## 旅程購買

**是誰**: 已買下某趟旅程、可永久存取其內容的學員
**怎麼取得**: 付款成功後依商品的方案項目授予 ← `pay-order` Rule 5
**跟誰不同**: 「旅程訂閱狀態」會過期，這個不會 ← `query-user-roles` Rule 2（撤銷時間）

## 旅程老師

**是誰**: 能維護某趟旅程內容的人
**怎麼取得**: **沒問過** → `questions/how-to-become-teacher.md`
**跟誰不同**: 目前沒有任何一條規則區分它與學員 —— 見下方「角色膨脹」
```

MUST: 「怎麼取得」推不出來時寫 `沒問過` 並開一張問題卡，不要留白。
留白跟「不需要」在檔案上長得一樣。

## 兩個角色沒有規則區分，就是同一個角色

MUST: 每個角色至少要有**一條規則**只約束它、不約束別人。

沒有的話，那個角色是**憑空多出來的**——它可能來自組織圖或畫面上的下拉選單，
而不是來自任何一條講定的行為。

判準：**把這兩個角色合併成一個，有沒有任何一條規則會變成錯的？** 沒有就合併。

角色膨脹的代價不是文件變長，是**權限規則的組合爆炸**：五個角色 × 十個操作
＝ 五十格要問，而其中三十格只是同一件事換名字。

## 別漏掉這三種

| 常被漏的 actor | 為什麼會漏 |
| --- | --- |
| **未登入的訪客** | 隱含在「使用者」裡，但它的能力完全不同 |
| **系統自己** | 排程、逾時、自動結算——`workout-logging` Rule 6.3 的「逾時自動結束」的執行者是系統 |
| **外部系統** | 金流回呼、webhook。它不是人，但它會觸發狀態改變 |

判準：**規則裡有沒有哪個動作，句子的主詞不是任何一個已列出的角色？**

## 產物格式

```markdown
# Actor

**更新於**: <YYYY-MM-DD>

各份 example map 的 Story 句子回指這裡的角色名，不重複定義。
一個人可以同時是多個角色。

## <角色名>

**是誰**: <一句話>
**怎麼取得**: <條件> ← <來源>
**跟誰不同**: <區分它的規則> ← <來源>

**能做什麼**
| 能力 | 來源 |
| --- | --- |
| 查詢自己的課程進度 | `query-progress` Rule 1 |

## 不是角色的東西

列出考慮過但判定不是角色的，以及理由——否則下一輪會有人再提一次。

| 考慮過 | 為什麼不是 | |
| --- | --- | --- |
| 管理員 | 需求裡沒有任何一條規則提到它 | 有需要時再開一張問題卡 |
| Alice | 那是實例，不是角色 | |
```

## 跟 `glossary.md` 的關係

兩者都是**跨 story 共用**的，由 CLARIFY 維護、下游只讀。分工：

| | 放什麼 |
| --- | --- |
| `glossary.md` | 名詞的定義、跨 story 的共用規則（Shared N） |
| `actor.md` | 誰在做事、怎麼取得那個身分、能做什麼 |

角色**名稱**的定義兩邊都可以寫，但**只寫一次**——寫在 `actor.md`，
`glossary.md` 的詞彙表回指它。同一個定義存兩處會漂移。

## 下游怎麼用它

`bdd-spec` 寫 `前置（狀態）` 規則時，主詞應該是 `actor.md` 裡的角色名。
出現一個沒在 `actor.md` 的角色，就是這裡漏了一個——那是可機械偵測的。

反向也成立：`actor.md` 列了某個角色，但沒有任何 `.feature` 的規則提到它，
代表它是憑空的。**兩個方向都要對得上**。
