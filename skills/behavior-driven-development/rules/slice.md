# Slice：一次做多大、先做哪一個、什麼時候算做完

判定「這一輪選的 slice 對不對」。讀這份的時機：流程第 3 步選 slice、第 5 步決定要不要繼續。

| # | 強度 | 規則 | 違反的後果 |
| --- | --- | --- | --- |
| L1 | `MUST` | 一個 slice 是一個 `Example:`（一個 `@example-N.M`）。同一時刻只處理一個 | 兩個場景一起做，失敗分不出是誰的 |
| L2 | `SHOULD` | 範疇內先做能形成**最小、最獨立**回饋的那一個：前置狀態最少、不依賴還沒做的場景。零值例子（定義照 `red.md` R5：在起點就綠、或只紅在共同的接線失敗——不是看斷言的值是不是 0）不排第一個，它證明不了任何東西 | 先做依賴最多的，第一個紅燈就混著三種原因 |
| L3 | `MUST NOT` | 跨出指定範疇去吸收相鄰的場景 | 沒人授權的行為被順手做掉，票的邊界失效 |
| L4 | `SHOULD` | `Scenario Outline` 的一張 `Examples:` 表算**一個**行為家族：先讓一列紅→綠，其餘列應該跟著綠；跟不上的那一列是另一個 slice。tag 對整張表生效，所以 Outline 上最窄的重跑範圍就是整張表——用名字或序號挑單一列，在並行與隨機順序下不可靠 | 逐列當成獨立 slice 會重複做同一件事；整張表一次做會把不同行為混成一個 |
| L5 | `MUST` | 一個 slice 做完，要同時有**行為訊號**（那個入口的完成條件）與**局部整潔**：沒有留下重複的步驟、寫死的資料、暫時碼 | 「先綠再說」留下的東西，下一個 slice 會疊在上面 |
| L6 | `COULD` | 由前面幾個 slice 的行為組合起來的場景，可以不寫新的產品程式碼就綠——前提是它在起點紅過，或照 `red.md` R5 做過突變驗證 | 為了讓它「有自己的紅」而硬寫重複的程式碼 |

## L2 的例子

範疇是「讀者還書」這條 `Rule:`，有三個例子：

```
@example-8.1  準時還書不算逾期        ← 需要：一筆已借出的借閱
@example-8.2  書況損壞被拒收          ← 需要：同上
@example-9.1  逾期滿 7 天要停權       ← 需要：8.1 的行為 ＋ 時間推進
```

先 8.1：它的前置狀態最少，而且 9.1 建在它上面。先做 9.1，紅燈會同時因為「還不能還書」與
「還不會算逾期」而紅，分不出哪個是這一輪該解的。

## L4 的例子

```gherkin
Scenario Outline: 依還書日算逾期天數
  ...
  Examples:
    | 還書日     | 逾期天數 |
    | 到期前一天 | 0        |
    | 到期日當天 | 0        |
    | 到期後一天 | 1        |
```

三列是同一條逾期規則的邊界，算一個 slice。若第四列是「逾期滿 7 天停權」，它驗的是另一條
規則——就算寫在同一張表，也當成另一個 slice 來紅、來綠。

## L5：什麼不算做完

| 狀況 | 為什麼還沒完 |
| --- | --- |
| 場景綠了，但步驟裡寫死了這個例子的日期 | 下一個例子會逼你改同一行——那是這個 slice 的債 |
| 場景綠了，但新增了一支跟既有步驟只差一個字的 step definition | 兩支函式會分岔 |
| `red` 入口：測試會失敗，但失敗訊息是 nil pointer | 訊號不對應這個 slice 的行為，下一步無從補起 |
