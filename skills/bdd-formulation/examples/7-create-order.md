# 建立訂單

**命令 · 最複雜的一份：多條規則共用一個象限、算出來的預期值、選用參數**

> 出處是一個線上課程平台。`@rule-N` / `@example-N.M` 是照本 skill 的規定補上的。
> **`When` 的形狀與一處斷言被改過**，理由見下方「兩處修改」。

> 其他範例：
> `1-video-progress` `2-submit-assignment` `3-deliver-course`
> `4-query-progress` `5-query-course-list` `6-query-product-list`
> `8-query-order` `9-pay-order` `10-cancel-order`

## 這份示範的四件事

### 1. 一個象限裝得下好幾條 Rule

`前置（參數）` 底下有四條：商品存在、商品上架中、項目不重複、折扣券有效。
**象限是分類，不是一條規則的名字。**

原始檔案把「商品必須存在**且**上架中」寫成一條，我拆成兩條——它們的失敗訊息
不同（`商品不存在` vs `商品已下架`），代表是兩個獨立的檢查。
合成一條的話，規則敘述說不出哪個例子在驗哪一半。

### 2. 算出來的預期值，計算規則不能只藏在數字裡

三個折扣例子的預期值是這樣來的：

```
抵用券 1000      9800 − 1000        = 8800
比例   0.9       9800 × 0.9         = 8820
兩張都用         9800 × 0.9 − 1000  = 7820      ← 比例先
                （9800 − 1000）× 0.9 = 7920      ← 面額先，不是這個
```

**7820 與 7920 差在套用順序**，而原始檔案的規則只寫「應正確計算折扣並標記折扣券
為已使用」——順序完全沒講，只存在於那個數字裡。

改成 `Rule: 折扣先套用比例折扣，再扣抵用券金額`。這一改，第三個例子從
「一個算出來的數字」變成「規則的證明」。

判準：**預期值是算出來的時候，讀規則敘述能不能自己算出同一個數字？**
不能，就代表規則漏講了什麼。

### 3. 斷言表的每一格都該是字面值

原始檔案這樣寫：

```gherkin
✗ And 訂單的查詢結果應包含：
    | 訂單編號格式 | 總價 | 付款期限     |
    | UUID 格式    | 9800 | 建立時間+3天 |
```

`9800` 是值，`UUID 格式` 和 `建立時間+3天` 是**規格描述**。三格混在一張表裡，
step definition 得替每一欄各寫一套解析——`UUID 格式` 要當 regex 用、
`建立時間+3天` 要當日期運算式用，而 `9800` 直接比對。**表格的形式在騙人**：
它看起來像資料，實際上是三種不同的東西。

拆成各自的步驟：

```gherkin
✓ And 訂單編號應為 UUID 格式
  And 訂單的付款期限應為建立時間之後 3 天
  And 訂單總價應為 9800
```

三支 step definition，各自意圖清楚，而且 `訂單總價應為 N` 這支在別的例子重用了五次。

### 4. 選用參數會讓 `When` 組合爆炸

原始檔案的同一個命令有**四種寫法**：

```
用戶 "X" 建立訂單，商品 ID 為 N，數量為 N                    5×
用戶 "X" 建立訂單，商品 ID 為 N，數量為 N，使用折扣券 N       4×
用戶 "X" 建立訂單，商品 ID 為 N，數量為 N，使用折扣券 N 和 N  1×
用戶 "X" 建立訂單，包含以下項目：（表格）                     2×
```

一個命令、四支 step definition。而且沒有收斂：三張折扣券要第五種，
「不指定數量」要第六種。那個 `1×` 的變體就是爆炸的第一格。

改法是把**選用的部分拆成獨立的 `And` 步驟**：

```gherkin
When 用戶 "Alice" 建立訂單，包含以下項目：
  | 商品 ID                              | 數量 |
  | 6f708192-a3b4-4c5d-8f60-718293a4b526 | 1    |
And 使用折扣券 b4c5d6e7-f809-41a2-94b5-c6d7e8f90a7b
And 使用折扣券 a3b4c5d6-e7f8-4091-83a4-b5c6d7e8f96a
```

兩支 step definition 覆蓋所有組合，而且折扣券要幾張都行。
代價是單商品的例子多三行——**用行數換樣板數，在這個尺度上是划算的**。

> 這裡的 `And 使用折扣券 <UUID>` 接在 `When` 之後，仍屬於同一個動作的一部分，
> 不算 SKILL.md 說的「兩個 `When`」。判準一樣：把它改寫成 `Given` 之後，
> 這個例子還驗得到原本要驗的事嗎？折扣券是**這個動作的參數**，不是前置狀態。

## 一個沒改、但值得問的地方

過期的折扣券與別人的折扣券，錯誤訊息都是 `折扣券無效`。

這可能是刻意的（不洩漏某張券存不存在、屬於誰），也可能只是沒細分。
**兩者在 `.feature` 裡看起來一模一樣**——如果是刻意的安全決定，
規則敘述該講出來；如果不是，那是兩個該分開的錯誤。

SPEC 不替這種問題選答案，寫進覆蓋表回報。
