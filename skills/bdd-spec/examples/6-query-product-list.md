## 這份示範的四件事

### 1. 空的象限寫在檔案裡，不只寫在報告裡

```gherkin
# 前置（狀態）：無。查詢商品不需要任何角色或狀態，未上架商品也看得到。

# 後置（狀態）：n/a。查詢不改變任何東西。
```

其他五份範例的查詢都要權限，這一份不要——**而「不需要權限」是一個決定，不是
疏漏**。沒有這行註解，下一個讀的人只會看到「這裡沒有權限規則」，
分不出是想過了還是漏了。

段落分隔（`# ===== 前置 =====`）讓四個象限在檔案裡看得見。掃一眼就知道
哪一格有東西、哪一格明確地空——不必開另一份文件對照。

**這是本流程的通則**：判斷的理由要跟判斷的結果放在同一個載體。覆蓋表講給
現在的人聽，會隨對話消失；檔案裡的註解留給之後的人，跟規格一起活著。

### 2. 巢狀結構分兩層斷言

商品清單的每一筆自己又帶一個「方案項目」集合。一張平表塞不下巢狀——
硬塞會長成 `| 商品 ID | 名稱 | 方案1類型 | 方案1天數 | 方案2類型 | … |`，
欄位數隨最多方案的那筆膨脹，而且少方案的列全是空格。

分兩層：先斷言清單本身，再對**需要驗巢狀內容的那幾筆**各下一句。

```gherkin
And 商品清單的查詢結果應恰好為：      ← 第一層：有哪幾筆、順序、沒有多的
  | 商品 ID | 名稱 | … |
And 商品 6f708192-a3b4-4c5d-8f60-718293a4b526 的方案項目應恰好為：        ← 第二層：挑一筆往下鑽
  | 方案類型 | 旅程 ID | 訂閱天數 |
```

不必每一筆都鑽。挑**形狀不同**的那幾筆就夠——這裡挑了商品「軟體設計模式精通之旅」（兩個方案）
與商品「軟體設計模式續訂」（只有訂閱），因為它們代表兩種結構。全部鑽一遍只是把 `Background`
抄第二次。

### 3. 表格空格 = 這一欄對這一列不適用

```gherkin
| 方案類型 | 旅程 ID                              | 訂閱天數 |
| 旅程購買 | a1f0c2d4-7b3e-4c81-9f2a-0d5e6b7c8a91 |          |
| 旅程訂閱 | a1f0c2d4-7b3e-4c81-9f2a-0d5e6b7c8a91 | 30       |
```

這解決了 [`4-query-progress.md`](4-query-progress.md) 與
[`5-query-course-list.md`](5-query-course-list.md) 之間那個沒解決的不一致：
挑戰題課程沒有進度百分比，一份整欄不列、一份填 `0`。

三種寫法各自的意思不同：

| 寫法     | 意思                           |
| ---      | ---                            |
| 整欄不列 | 這個查詢的回應**沒有這個欄位** |
| 填 `0`   | 有這個欄位，**值是零**         |
| 空格     | 有這個欄位，**對這一列不適用** |

第三種通常才是對的（挑戰題沒有「進度 0%」這回事，它就是沒有進度）。
但**哪一種對取決於 API 實際回什麼**——這仍然是 CLARIFY 該問的一題，
SPEC 只負責讓三種寫法的差別被看見。

### 4. 「前置（參數）」是最容易漏的一格，這份有

```gherkin
Rule: 前置（參數）- 狀態篩選值必須是既有的商品狀態

  Example: 用不存在的狀態值篩選時操作失敗
```

查詢很容易只寫快樂路徑——查得到什麼、格式對不對。傳一個不存在的篩選值進去
會怎樣，常常沒人問。四象限的價值就在這裡：它會逼你發現這一格是空的。

## 原始檔案裡被移除的那個 Example

```gherkin
Example: 商品資訊應包含完整欄位          ← 已移除
  When 用戶 "Alice" 查詢商品清單
  Then 操作成功
  And 商品 6f708192-a3b4-4c5d-8f60-718293a4b526 的資訊應為： …
  And 商品 6f708192-a3b4-4c5d-8f60-718293a4b526 的方案項目應包含： …
```

兩個問題：

**名字描述的是回應的屬性，不是一個情境。** 「應包含完整欄位」沒有「什麼情況」
也沒有「什麼結果」，測試紅了的時候這一行說明不了壞在哪。
句型應是 `<情境條件>時<預期結果>`。

**它驗的東西跟 `不帶篩選時連已下架的商品都回傳` 完全重疊。** 同一個 `When`、
同一批斷言，只是換個角度再講一次。重複的例子不會多驗到任何東西，
但每次規格改動都要跟著改兩處——遲早會有一處沒改到。
