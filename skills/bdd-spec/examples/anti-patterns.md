# 反例 —— 文法跑掉的樣子

兩個反例。它們都**能跑、能解析、測試也會過**——這正是問題：
壞掉的地方不會報錯，只會在半年後變成三十支沒人想維護的 step definition。

讀這份的時機：寫完一份 `.feature` 之後，或 `check_spec.py` 的樣板數看起來不對。

---

## 反例一：散文式寫法

拿 [`1-video-progress.md`](1-video-progress.md) 的同一條規則，用散文式重寫一次——
兩種寫法驗的行為完全相同：

```gherkin
Rule: 影片進度必須單調遞增

  @rule-2 @example-2.2
  Scenario: 進度不可倒退
    Given Alice 這位學生已經把物件導向基礎看到 70%
    When 她把播放器拉回 60% 的位置
    Then 系統不會把她的進度往回改

  @rule-4 @example-4.1
  Scenario: 看完整支影片就算修完
    Given Alice 已經看到 90%
    And 這門課是影片課程
    When 她把剩下的 10% 看完
    Then 這門課顯示為修完
```

讀起來比封閉文法自然得多。代價是每個場景都自成一格：

|                                  | 場景 | 不重複樣板 | 只出現一次 |
| ---                              | ---  | ---        | ---        |
| 上面兩個場景                     | 2    | 7          | 7          |
| `1-video-progress.md` 的對應兩個 | 2    | 5          | 0          |

七個樣板、七支只會被呼叫一次的 step definition，而它們**只覆蓋兩個場景**。

### 壞在哪

**每個場景自己造前提。** 「已經把物件導向基礎看到 70%」和「已經看到 90%」是
兩種講法，於是兩支 step definition。封閉文法一次把世界播好，場景只講前置狀態。

**沒有成敗的概念。** `系統不會把她的進度往回改` 把「失敗」藏進動詞裡，
於是每一種失敗都要自己的講法。統一成 `操作失敗` ＋ `錯誤訊息應為 "…"`
之後，所有失敗共用兩支。

**斷言只講變化。** `這門課顯示為修完` 沒說進度變成多少、也沒說別的課有沒有被動到。
一個標對狀態但順手清空進度的實作，會通過這個測試。

**代名詞。** `她把剩下的 10% 看完`——「她」是誰要往上讀才知道，而 step definition
接不到這個資訊。封閉文法一律寫全名：`用戶 "Alice"`。

### 這不是紙上談兵

本 skill 的**舊版**在一個健身追蹤專案上實跑過，五個 `.feature`：

```
76 個場景 → 208 個不重複步驟樣板，其中 172 個只出現一次
```

**step definition 比場景還多。** 那個專案的領域不同，但走的正是上面這條路。

## 反例二：`Then` 沒有先講成敗

摘自一份整體良好的檔案（完整版見 [`3-deliver-course.md`](3-deliver-course.md)）——
同一份裡其他例子都用 `操作失敗` 開頭，只有成功路徑不用：

```gherkin
✗ Then 課程 1a2b3c4d-5e6f-4708-9a1b-2c3d4e5f6071 交付成功，用戶 "Alice" 收到獎勵經驗值 300，新等級 3
✗ Then 用戶 "Alice" 收到總經驗值 600，新等級 5，升級狀態為 true

✓ Then 操作成功
  And 用戶 "Alice" 在課程 1a2b3c4d-5e6f-4708-9a1b-2c3d4e5f6071 的狀態應為 "已交付"
  And 用戶 "Alice" 的經驗值應為 300，等級應為 3
```

**三個問題疊在一起：**

**沒有共用的成功樣板。** 失敗路徑統一成 `操作失敗`，成功路徑卻每次自己講——
於是「成功」這件事有幾種說法就要幾支 step definition。

**複合斷言吞掉失敗訊息。** `收到總經驗值 600，新等級 5，升級狀態為 true`
一次斷言三件事。失敗時你只知道「這句不成立」，不知道是經驗值算錯、等級沒升、
還是升級旗標沒設。拆成三行，失敗的那一行就是答案。

**`升級狀態為 true` 是實作語彙。** `true` 不會出現在 example map 或 glossary 裡——
它從實作滲進了規格。業務講的是「升級了」，不是「旗標為真」。

## 自我檢查

```bash
python3 <skill>/scripts/check_spec.py <專案根>
```

它會印出樣板數。沒有及格線，但有兩個實測參考點：

|                                   | 場景 | 不重複樣板 | 只出現一次 |
| ---                               | ---  | ---        | ---        |
| 反例一（散文式）                  | 76   | 208        | 172        |
| `1-video-progress.md`（封閉文法） | 7    | 10         | 3          |

只出現一次的樣板數逼近場景數，就代表文法沒有真的套上。
