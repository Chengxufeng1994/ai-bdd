# FEATURE MAPPING — 把整個 feature 攤成一張流程圖

| | |
| --- | --- |
| **職責** | 把整個 feature 攤成「規則 × 例子 × 步驟 × 結果」的列，逐步找出缺的流程與反例，寫成補問 |
| **讀** | 流程內：`specs/ongoing/<date>-<feature>/spec.md`（`待對焦`）與同目錄 `discovery.md` 的 `## 原文`；單獨：一段 feature 的描述 |
| **寫** | 流程內：只寫 `spec.md` 的 `## Open Questions`；單獨：不寫檔。地圖只印在終端 |
| **上游** | `spec`（第 5 步第一個呼叫）；也可單獨使用 |
| **下游** | `example-mapping`（照樣跑完，兩張圖的洞一次帶回 `discovery`） |
| **不做** | 不訪談、不改 US／FR／AC、不寫狀態、不判就緒、不寫 Gherkin、不產出 `feature-map.md` |

**問題寫下來，不當場問。** 原始做法是在工作坊裡逐步問「這裡還可能發生什麼」。這裡是 SPEC：
當場問到的答案寫不進 `discovery.md`，FR 也標不出 `← Q-<n>`，只活在這一次對話裡。每個問題都寫成
補問一列，讓 `discovery` 開成一題去問。

## 使用時機

- `spec` 寫完 `spec.md`，第 5 步開始診斷
- 流程長、規則藏在步驟裡的 feature（申請、審核、結帳），四色卡攤不出規則
- 想知道一個 feature 的替代流程與反例寫齊了沒
- 單獨拿一段 feature 描述來攤，不走 BDD 流程

**方向**：本 skill 看**整個 feature 的寬度**——流程有沒有斷、分支有沒有寫；`example-mapping` 看
**一則 story 的深度**——每條規則有沒有例子撐住。兩個都跑，先寬後深。

## Skill Boundaries

| 情況 | 改用 |
| --- | --- |
| 要看一則 story 的規則有沒有例子撐住、判就緒 | `example-mapping` |
| 要把紅卡或補問逐一問到收斂 | `discovery`（補問）、`clarify`（紅卡） |
| 要把 feature 寫成業務方讀的驗收旅程 | `spec-by-example` |
| 一則 story 太大要切 | `story-splitting` |
| 要改 FR 或 AC 的寫法 | `spec`，本 skill 只指出來 |

## 流程

| 步驟 | 做什麼 | 要問使用者嗎 |
| --- | --- | --- |
| 1 | 認模式：流程內或單獨 | — |
| 2 | 排主流程：從 `## 原文` 抽出整個 feature 的步驟順序 | — |
| 3 | 攤列：每條 AC 一列，依 FR 分組，對齊到主流程 | — |
| 4 | 跑三條診斷 | — |
| 5 | 流程內：缺口寫進補問；印地圖與結果，交回 `spec` | — |

### 1. 兩種模式

| 模式 | 輸入 | 輸出 |
| --- | --- | --- |
| 流程內 | `spec.md` 狀態 `待對焦`，由 `spec` 第 5 步呼叫或使用者指定 | 地圖 ＋ 三條診斷；缺口寫進 `spec.md` 的 `## Open Questions` |
| 單獨 | 一段 feature 的描述 | 同樣的地圖與診斷，缺口只回報，**不寫任何檔案** |

### 2. 排主流程 —— 原文就是錨定敘事

原始做法開工前會寫一段「錨定敘事」：具體、寫實的情境，讓人開始想、開始問。這裡不另寫，
**`discovery.md` 的 `## 原文` 就是它**——需求方自己講的那段話。從原文抽出這個 feature 從頭到尾的
步驟順序，當地圖最上面一排的標題卡（🟨）。單獨模式用使用者給的描述。

主流程跨 story：借還書的主流程是「借書 → 拿借書單 → 續借 → 還書」，四步可能分屬三則 US。
**按 story 分開攤，就看不到流程在哪裡斷了**——這正是本 skill 存在的理由。

### 3. 攤列

每條 AC 一列，同一條 FR 的 AC 排在一起：

| 卡 | Feature Mapping | `spec.md` |
| --- | --- | --- |
| 🟦 | business rule | `FR-<n>` |
| 🟩 | example | `AC-<n>.<m>` 那一行 |
| 🟨 | step | 它的 Given／When，對齊到主流程的哪一步 |
| 🟪 | consequence | 它的 Then |

地圖只寫編號與幾個字，不抄 AC 全文——規則與例子只住在 `## User Stories`。

```
主流程 🟨  櫃台借書 ─── 拿借書單 ─── 上網續借 ─── 櫃台還書
              │                          │
🟦 FR-1  借出加 14 天，遇休館日順延      │
   🟩 AC-1.1  週四借出 ●─────────────────────── 🟪 到期日是兩週後的週四
   🟩 AC-1.2  第 14 天休館 ●─────────────────── 🟪 順延到下一個開館日
🟦 FR-2  到期前可續借一次                │
   🟩 AC-2.1  第一次續借 ────────────────●───── 🟪 到期日延 14 天
              ↑
  ⚠ 這一步只有「讀者證驗得過」一種走法

診斷：主流程 4 步、🟦 2、🟩 3
  ⚠ 替代流程：「櫃台借書」沒有讀者證驗不過的例子
  ⚠ 反例：FR-2 沒有「已經續借過一次又來續借」的例子
  ✓ 結果不同的列都有規則解釋
```

### 4. 三條診斷

| 診斷 | 怎麼看 | 找到時 |
| --- | --- | --- |
| **替代流程** | 主流程的每一步問「這裡還可能發生什麼」「使用者還能做什麼」。原文或問答提到、卻沒有一列走過的走法，就是缺口 | 補問一列 |
| **反例** | 每條 FR 至少要有一列是規則**不**適用的情況，畫出規則的邊界。只有正例的規則，不知道它在哪裡停 | 補問一列 |
| **結果沒有規則** | 兩列步驟相同、結果不同，卻沒有一條 FR 說明為什麼不同 | 補問一列 |

**替代流程只從來源裡找。** 「這裡還可能發生什麼」可以無限問下去；能寫成缺口的，是原文、
`discovery.md` 的問答或 `spec.md` 其他節**已經提到**、卻沒有任何一列走過的走法。來源完全沒提的
可能性，寫進判讀當觀察，不開補問——否則每個 feature 都會退回 discovery 十次。

**缺口分兩種，去處不同：**

| 缺口 | 去處 |
| --- | --- |
| 來源**沒有答案**：提到了這個走法，卻沒人說過該怎麼辦 | `## Open Questions` 一列，回 `discovery` 問 |
| 來源**有答案**，只是 `spec` 沒把它寫成 AC（例：問答裡講過「讀者證系統沒回應就先手寫登記」，卻沒有一列走過） | 寫進判讀，指名是哪一題；交回 `spec` 補 AC，**不開** `## Open Questions`——開了會重問一題已經答過的 |

MUST NOT: 自己替缺口補一列 AC，或把 FR 改寫成涵蓋那個分支。那是規則，規則只能來自需求方的答案；
就算答案在來源裡，寫成 AC 也是 `spec` 的事。

判讀沒有數字門檻，但每一條都要寫出理由：哪一步、哪條 FR、哪兩列。拿不準是不是缺口時判「不是」，
寫進判讀，讓需求方在就緒問句時決定。

### 5. 寫補問、交回

流程內：每個「來源沒有答案」的缺口寫成 `## Open Questions` 一列，照 `spec-format.md` 的寫法說清楚
**影響什麼定不下來**；原本是「（無）」就換掉。「`spec` 漏寫了 AC」的列在判讀裡，交回時一起告訴 `spec`。

```markdown
- 櫃台借書沒有讀者證驗不過的例子：讀者證系統沒回應、讀者證已停用時書借不借得出去、要不要留紀錄 —— 影響 FR-1 的借書步驟、US-2 的續借
```

印地圖與診斷結果，交回 `spec`。**有沒有缺口都照樣接著跑 `example-mapping`**：兩張圖找到的洞一次帶回
`discovery`，需求方只要回答一輪。

## 產物

流程內唯一會動的是 `spec.md` 的 `## Open Questions`，只加列、不改既有的列。地圖是終端輸出。

MUST NOT: 產出一份 `feature-map.md`，或在 `spec.md` 加一節地圖。圖上每張卡都已經住在別處——規則是
`FR`、例子與步驟與結果是 `AC` 的 Given／When／Then、串起來的流程是 `acceptance/` 的旅程。再寫一份
就是同一件事兩份，遲早不一樣。

## Verification

交回前逐項確認；任何一項答「否」就不交——修好，或在回報裡明說哪一項沒過：

- [ ] 主流程是從 `## 原文`（單獨模式：使用者的描述）抽出來的，跨 story 排成一排
- [ ] 地圖上每條 AC 都在一列上，掛在它的 FR 底下，對齊到主流程的某一步
- [ ] 三條診斷都給了結果；每個缺口指名了哪一步、哪條 FR 或哪兩列
- [ ] 每個缺口都能指到原文、問答或 `spec.md` 裡提到它的地方；答案已在來源裡的沒有寫進 `## Open Questions`
- [ ] `spec.md` 只動了 `## Open Questions`，只加列；US／FR／AC、狀態都沒變
- [ ] 沒有對需求方提任何問題；單獨模式沒有寫任何檔案
