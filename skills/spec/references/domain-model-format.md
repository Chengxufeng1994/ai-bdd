# `domain-model.md` 的骨架

路徑 `specs/domain-model.md`——**根層，跨 feature**。`spec` 每寫完一個 feature 的
`spec.md` 就增修它。它比任何一份 `spec.md` 的技術部分活得久：技術部分實作一開始就會過期；
domain model 要留下來。

每個 feature 只**增修**，不重寫。改了既有條目要寫「原本是什麼、為什麼改」。

```markdown
# Domain Model

**更新於**: <YYYY-MM-DD> · **最後更新 feature**: <date>-<feature>

## 聚合

### <聚合名>

**是什麼**: 一句話
**邊界**: 哪些東西跟它一起變更、哪些不是
**來源**: <date>-<feature> FR-N

**不變條件**（任何時刻都必須為真）

| 條件 | 來源 | 被誰保證 |
| --- | --- | --- |
| 一個使用者最多一筆進行中的訓練 | 2026-09-09-log-a-workout FR-1 | Workout 聚合 ＋ DB 唯一索引 |

## 跨聚合的規則

不屬於任何單一聚合的。寫明為什麼放不進去。

## 修訂紀錄

| 日期 | feature | 改了什麼 | 為什麼 |
| --- | --- | --- | --- |
```

**不變條件與 `.feature` 的 `Rule:` 有什麼不同**：`Rule:` 是**某次操作要滿足
的行為**，不變條件是**任何時刻都必須為真的狀態**。前者用場景驗，
後者多半要靠型別、建構子或資料庫約束保證——它們的實作位置不同，所以要分開寫。
