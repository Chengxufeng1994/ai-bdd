# 反面教材

每一項都是實際會讓 skill 失效的寫法。附上為什麼失效，以及改法。

## 1. description 只描述功能，沒有觸發條件

```yaml
# ✗
description: 這個 skill 會產生會議紀要。
```

文法正確、YAML 合法、意思清楚——但模型不知道**使用者說什麼的時候**該用它。
這是最隱蔽的錯誤，因為它看起來完全沒問題。

```yaml
# ✓
description: >
  把逐字稿或會議筆記整理成結構化會議紀要。
  觸發詞：「整理會議記錄」「產生會議紀要」「幫我整理一下今天的會」
  「開會內容整理」「會議摘要」。
  English: meeting minutes, summarize meeting, meeting notes.
```

## 2. 觸發詞裡有通用詞

```yaml
# ✗
觸發詞：「處理」「整理」「做一下」「幫我看看」
```

這些詞會在無關情境瘋狂誤觸發。**誤觸發比不觸發更難察覺**——不觸發使用者會馬上
發現「怎麼沒用到」，誤觸發則是安靜地產出一份用錯方法的結果。

刪掉一個過於通用的觸發詞，通常比多加五個精準的更有價值。

## 3. 流程步驟無法照做

```markdown
# ✗
## 流程
- 分析信件
- 回覆
```

「分析」是什麼？分析出什麼？看什麼欄位？

```markdown
# ✓
## 流程
1. 讀取來信全文
2. 識別寄信人名稱、主旨、核心訴求
3. 判斷情緒傾向（正面／中性／負面／緊急）
4. 若情緒為負面或緊急，先詢問使用者回覆策略
5. 按輸出格式產出草稿
```

## 4. 整份都是 MUST

```markdown
# ✗
MUST: 讀取全文。
MUST: 識別寄信人。
MUST: 判斷情緒。
MUST: 使用正式語氣。
MUST: 結尾加上簽名。
```

模型分不出哪一條是真的不能違反。結果等同於全部都沒標。

一份 skill 通常只有一兩條真正的 `MUST`／`NEVER`，其餘是 `SHOULD`。檢驗方法：
**想得出任何一種合理例外的，就不是 `MUST`。**

## 5. 只有命令，沒有理由

```markdown
# ✗
NEVER: 不可先產生 Gherkin 再回頭補例子。
```

```markdown
# ✓
NEVER: 不可先產生 Gherkin 再回頭補例子。順序顛倒會導致使用者直接審閱模型的
清單並全部點頭，那是假的 discovery——它製造了「我們討論過了」的錯覺，比不做更糟。
```

模型有理論心智。給它理由，它能處理你沒預見的情況；只給命令，它遇到邊界只能照
字面硬做。

## 6. 放了參考檔卻沒指路

```
my-skill/
├── SKILL.md          ← 完全沒提到下面這些檔案
└── references/
    ├── api-spec.md
    └── patterns.md
```

**子目錄的檔案不會自動載入。** 沒有在 SKILL.md 裡寫「詳見 `references/api-spec.md`」，
模型根本不知道那個檔案存在。這些檔案等於不存在，卻讓維護者以為 skill 已經涵蓋
了那些內容。

## 7. Skill Boundaries 空白或含糊

```markdown
# ✗
## Skill Boundaries
- 本 skill 專注於自己的職責。
```

等於沒寫。Boundaries 的價值在於**指到具體的替代方案**：

```markdown
# ✓
## Skill Boundaries
- 要完整的建立流程（產草稿 → 跑測試 → 迭代）→ 改用 `skill-creator`
- 要最佳化 description 的觸發率 → 也在 `skill-creator` 裡
- 本 skill 只做規範與稽核兩件事
```

## 8. 例子全部來自同一個場景

skill 寫給 Figma 用，於是每個例子都是 Figma。

【推論，未實測】規則與例子的偶然特徵混在一起時，讀者（人或模型）沒有對照組可以
分辨哪些是規則本身。讓例子跨越不同領域，等於提供對照組——共通的部分才是規則。

具體要幾個領域沒有依據可循。可操作的檢驗是：**遮住例子裡的領域名詞後，規則還讀
得懂嗎？** 讀不懂，就表示規則的敘述依賴了那個場景。

## 9. 巢狀目錄分類

```
skills/
└── clarify/
    └── example-mapping/
        └── SKILL.md      ← 能跑，但 claude plugin validate 掃不到
```

執行時有效，但驗證工具不遞迴——這個 skill 永遠不會被檢查。問題要等到它靜默
失效才會浮現。改成扁平 `skills/bdd-clarify-example-mapping/`。

## 10. 本文塞滿只有特定情況才需要的內容

SKILL.md 超過 500 行時，多半是把「只有處理 X 情況才要讀」的段落也放進了主檔。
本文在每次觸發時全額計費。把那些段落下放到 `references/`，主檔留骨架與指路。
