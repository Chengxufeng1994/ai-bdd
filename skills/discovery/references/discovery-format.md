# `discovery.md` 的骨架

`discovery` 建檔與每一輪記答案時讀它；`clarify` 收斂紅卡時讀它；`spec` 從它寫
`spec.md`（需求部分與技術部分都是）；`status.py` 從它的 `## Open Questions` 算進度，
`check_spec.py` 從它查 `← Q-<n>` 與 `← PRD §n`。

一個 feature 一份，路徑 `specs/<date>-<feature>/discovery.md`。它是**問答紀錄，不是規格**：
這裡沒有 FR、沒有 AC、沒有 Gherkin。規則由 `spec` 寫在 `spec.md`，每一條行尾指回這裡。

完整範例：[`../examples/minimal-discovery.md`](../examples/minimal-discovery.md)。

---

## 章節順序

| 章節 | 裝什麼 | 誰寫 |
| --- | --- | --- |
| `## Document Overview` | 狀態、最後更新、結束方式、`### 版本修訂歷史`（含「需求方確認建檔」一列）、`### 核心關係人` | 第 0 件事建，每輪更新 |
| `## 粗切 story` | `**切法**` 一行 ＋ 每則一行 `- **US-<n> · <slug>**　身為…我想…以便… ← PRD §n`。**沒有 FR／AC** | 第 0 件事 |
| `## Open Questions` | 五欄表 ＋ 每題的小節（下面） | 每一輪 |
| `## 原文` | 需求方的話，逐字，`§<n>` 編號 | 第 0 件事，之後**不得改寫** |

### 狀態

| 狀態 | 誰寫 | 什麼時候 |
| --- | --- | --- |
| `澄清中` | `discovery` | 建檔時 |
| `已收斂` | `discovery` | 前沿空了、『待答』零列、結束方式 `收斂` |
| `澄清中` | `spec` | 退回來時（修訂歷史記一列「回頭：<原因>」） |

`待對焦`／`已對焦` 是 `spec.md` 的狀態，不出現在這份檔。

`結束方式` 四選一：`收斂`／`阻塞`／`零進展`／`喊停`，建檔時寫 `—`。

## Open Questions：表是索引，小節是決策史

一個檔同時服務兩種讀者：`status.py` 讀表算進度，人讀小節查來龍去脈。

````markdown
## Open Questions

表是索引，給腳本讀；小節是決策史，給人讀。

| Q | 問題 | 面向 | 狀態 | 答案 |
| --- | --- | --- | --- | --- |
| Q-1 | 月租費帳務在不在範圍 | — | 已答 | 名單與期限在，錢不在 |
| Q-2 | 消防法規對閘門的要求 | 降級 | 待答 | — |
| Q-3 | 機車費率 | — | n/a | 本期不做機車 |
| Q-4 | 同一戶登記兩台車要不要都給月租證 | 邊界 | n/a | 現行規定一戶限一證，這次不改 |

**`面向` 欄不可省。** `status.py` 用它算追問覆蓋——十六個面向各自掃過沒有，
業務十一個與技術五個各印一欄。省掉它不會報錯，只會讓覆蓋率永遠顯示 0，
而那是靜默地錯。

### Q-2 消防法規對閘門的要求

**狀態**：待答　**輪次**：3　**該問誰**：消防設備師、柵欄廠商

2026-09-09 問管委會 → 「我知道有規定但背不出來，不敢猜」

**擋住**：monthly-pass（月租戶刷卡出場開柵欄）
````

小節可以多兩個選填欄位：`**誰答的**：<關係人>`，以及 `**歸屬**：<這個答案要進哪一節>`。
`歸屬` 的值域是 `spec.md` 的章節名——需求部分的節，或技術部分的七節（`Tech Stack`／`Commands`／
`Project Structure`／`Code Style`／`Boundaries`／`Implementation Decisions`／`Testing Decisions`）；
`Risks` 是 `plan.md` 的節，風險的答案標它。這一欄讓 `spec` 與 `plan` 知道該寫進哪一節，不必從
問題文字猜。

### `面向` 的值域

`面向` 不是自由文字。合法值只有兩組共十六個，或者 `—`：

- **業務面向（十一個）**：〈追問清單〉與〈非功能面向〉兩張表
  （[`../../discovery/SKILL.md`](../../discovery/SKILL.md)）列出的名稱
  ——空與零、邊界、重複、時序、權限、失敗、時間、規模、降級、時限、可觀測
- **技術面向（五個）**：
  [`../../discovery/references/technical-probes.md`](../../discovery/references/technical-probes.md)
  的五個章節標題——seam、模組邊界、介面與型別契約、排序契約／決定性、
  既有資產／測試慣例

機械可查核的清單以 `../../discovery/scripts/status.py` 的 `DIMS` 常數為準——這裡不重複列一份
會漂移的副本，兩邊不一致時以那支腳本為準（跟 `status.py` 自己處理
`TECH_DIMS`／`technical-probes.md` 落差的方式一樣）。

**這一欄是 `status.py` 算追問覆蓋的唯一來源。** 填一個不在上面清單裡的值（例如
「範圍」「法規」）不會報錯——那一格就是不會被任何一個面向認領，覆蓋率因此會
**看起來永遠是 0**，而那正是這條鏈最容易靜默地錯的地方。

`—`：開場的範圍題不屬於任何一個探針面向——它問的是會不會改變範圍、角色
清單，不是十一個業務面向或五個技術面向裡的任何一個。上面 Q-1、Q-3 都是這種
範圍題，`面向` 填 `—`，不計入追問覆蓋。

### 狀態值

只有三種，不得混用同義詞：

| 狀態 | 意思 |
| --- | --- |
| `已答` | 有答案，答案欄已填；小節有答案原話與 `**誰答的**` |
| `待答` | 還沒有答案，答案欄填 `—` |
| `n/a` | 這個面向不適用，答案欄要寫**為什麼不適用**，不能空著——空著跟「懶得問」在表格上長得一樣 |

### `輪次` 與 `信心`

問題有自己的小節時，可以在狀態列加這兩個欄位：

- **輪次**：這題被問到第幾輪還沒收斂。用來判斷是不是該換個問法，或該停下來
  確認方向錯了——連續好幾輪同一題還在待答，通常代表問錯層次
- **信心**：只在**已答**時才有意義，標這個答案有多篤定——`低`／`中`／`高`。
  「我知道有規定但背不出來，不敢猜」這種答案信心低，即使狀態已經是「已答」，
  也該讓下游知道這條可能要回頭確認

兩者都是選填：一題一輪就答完、答案篤定，不必特地寫。

## 原文

```markdown
## 原文

需求方 2026-10-02 口述，由 discovery 逐字記錄；§ 編號是記錄時加的，原文沒有。

§1 停車場要開始收費，訪客跟月租戶分開算。
§2 訪客進場抽一張票。
§3 前半小時免費，之後每小時 30 元。
§4 月租戶刷卡就直接出去。
```

MUST: 逐字。需求方帶著現成文件來，整份貼進來；口述的，照講的記，不潤飾、
不補主詞、不把「大概半小時」改成「30 分鐘」——那個「大概」正是下一步要問的題。

`§<n>` 是記錄時加的段落編號，給 `← PRD §n` 用。原文自己有章節編號就沿用，
不另編。

MUST NOT: 建檔之後改寫這一節。要補充就在 `## Open Questions` 開一題；原文被改寫，每個 `← PRD §x` 從此指向一句沒人說過的話，而且不會報錯。
