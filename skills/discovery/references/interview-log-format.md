# `interview-log.md` 的骨架

本 skill 唯一寫的檔，路徑 `specs/ongoing/<date>-<feature>/interview-log.md`。它是**流水帳**，不是規格：
需求方帶來什麼話、問了哪些題、誰怎麼答。規則由 `spec` 讀它寫進 `spec.md`——本 skill 不碰 `spec.md`。
格式借自 aixbdd `clarify` 的 clarify-log（Session／逐題的提問、答案、補充、收斂結果／Confirmed Decisions／
Remaining Open Items），出處見 repo 的 `RESOURCES.md`。寫好的樣子 → `../examples/interview-log.md`。

## 五節，順序固定

| 節 | 寫什麼 | 怎麼改 |
| --- | --- | --- |
| `## 原文` | 需求方帶來的話，逐字，`§<n>` 編號 | 建檔時寫一次，之後不改 |
| `## Session` | 一次訪談一個 `### <日期> · <建檔／續跑／補問／喚醒>`：主題、需求方、核心關係人與決策權、代演與否、粗切 story、需求方確認建檔 | 只追加 |
| `## 問答` | 一題一節 `### Q-<n> · <問題>` | 只追加；唯一可改的是那一題的 `**狀態**` |
| `## Confirmed Decisions` | 意圖陳述與已拍板的決定，每條指回 `Q-<n>` 或 `§n` | 每次結束時重寫 |
| `## Remaining Open Items` | 還待答的題與它掛在誰身上；`**結束方式**` | 每次結束時重寫 |

**為什麼只追加。** 這份是證據，跟 `## 原文` 一樣不改：`spec.md` 的 `## Open Questions` 表是 `spec` 從這裡
整理出來、給規則引用的版本；兩處對不上時以這裡的原話為準。改寫這裡，就沒有東西可以拿來對了。

## 骨架

````markdown
# interview-log：<feature 的一句話>

## 原文

<需求方> <日期> 帶來的<文件／口述>，逐字；§ 編號是記錄時加的。

§1 …

## Session

### <日期> · 建檔

- **主題**：<一句>
- **需求方**：<誰>
- **代演**：否（或：代演（需求方）／代演（開發者），待 <誰> 驗收）
- **核心關係人**：

  | 關係人 | 負責什麼 | 決策權 |
  | --- | --- | --- |
  | <誰> | <負責什麼> | <照他講的填；不知道寫「（未問）」> |

- **粗切 story**（暫定，沿 §<n> 的使用者目標切）：
  - `US-1 · <slug>` —— 身為<角色>，我想…，以便… ← §<n>
- **需求方確認建檔**：<誰> →「<他點頭的原話>」

## 問答

### Q-<n> · <問題，一句>

**面向**：<十六個面向之一，或 —>　**狀態**：待答
**上下文**：<原文哪一段、前面哪一題的答案、查到的事實>
**猜測**：<你以為的答案與為什麼；或「這題我不建議猜——要去問 <誰>」>
**該問誰**：<核心關係人表裡的人>（待答時）
- <日期> <誰> →「<答案原話>」
**誰答的**：<誰>（答定時追加）
**收斂結果**：<一句結論>（答定時追加）

## Confirmed Decisions

### 意圖陳述（Q-<n>）

- **Outcome**：…
- **User**：…
- **Why now**：…
- **Success**：…
- **Constraint**：…
- **Out of scope**：…

### 已拍板

- <決定> ← Q-<n>

## Remaining Open Items

**結束方式**：<收斂／阻塞／零進展／喊停>　**日期**：<日期>

| Q | 掛在誰身上 | 等什麼 |
| --- | --- | --- |
````

沒有內容的節保留標題並寫為什麼空（「（無）——待答 0 題」）。

## 一題的欄位

| 欄 | 寫什麼 |
| --- | --- |
| `**面向**` | 十六個面向之一或 `—`；值域與 `spec.md` 的 `面向` 欄相同，機械清單以 `../scripts/status.py` 的 `DIMS` 為準。`status.py` 的追問覆蓋只靠這一欄 |
| `**狀態**` | `待答`、`已答`、`n/a`（不適用、這題不該問）、`失效`（被另一題取代）。**整題唯一可以改的一格** |
| `**上下文**`、`**猜測**` | 問出口時那則訊息的上下文與猜測，原樣記；對方回「不是」時，猜測照留，答案行寫正確答案（決策史） |
| `**該問誰**` | 待答、阻塞時必填，指向某一場 Session 登記的核心關係人 |
| `**來自**` | 選填：`補問 —「<spec.md 裡那一題的來自，逐字>」`、`喚醒 —「<需求方的原話>」` |
| 答案行 | `- <日期> <誰> →「<原話>」`，一次一行，**只追加**；答案帶出的例子原樣記在同一行或下一行 |
| `**誰答的**`、`**收斂結果**` | 答定時追加。`n/a`／`失效` 的收斂結果寫為什麼不用問、或被哪一題取代 |
| 堆 | 答不出來時追加一行 `**堆**：可解，之後再問`／`阻塞`／`失效` 與為什麼 |

`Q-<n>` 全域唯一、不重排；跟 `spec.md` 的 `## Open Questions` 共用同一個序列——新開一題用兩份檔裡最大的號再加一。

標題、`**面向**`、`**狀態**` 三樣照上面的形式寫：`status.py` 靠 `### Q-<n> · `、`**面向**：`、`**狀態**：` 數題，
缺一樣，那一題會被報成解析不出來。
