# DISCOVERY — 把需求問到完整，只記問答

| | |
| --- | --- |
| **職責** | 把一段需求（想法或別人寫的 PRD）收成逐字原文與粗切 story，再一題一題問到猜得中需求方的反應，每個答案逐題記下，最後讓需求方對一段意圖陳述說 yes |
| **讀** | 需求本身（描述、文件內容或路徑），或 `specs/ongoing/<date>-<feature>/interview-log.md`（續跑）；`spec.md` 狀態 `澄清中` 時只讀它 `## Open Questions` 的待答題 |
| **寫** | `specs/ongoing/<date>-<feature>/interview-log.md`，只追加（`references/interview-log-format.md`） |
| **上游** | 無（可單獨使用）；`spec` 寫規格時開了待答題、把 `spec.md` 改回 `澄清中` 時再跑 |
| **下游** | `spec`（讀紀錄寫 `spec.md`），由使用者叫 |
| **不做** | 不寫 `spec.md`（只讀它的待答題）、不寫 FR／AC／Gherkin／規則草稿、不自己填答案、不改寫 `## 原文` 與已記的答案、不寫 `plan.md`／`.feature` |

**把需求攤成一棵設計樹。** 每個決定都會岔出依賴它的下一批決定。**前沿**是所有
**前提已經定案**的決定——現在就問得出口、不必先猜任何還沒聽到的答案的那些題。
從前沿挑**影響最大的一題**問，等答案，重算，再挑下一題。下一題可以依賴這一題的答案——這正是
一次只問一題的理由。

**不寫規格。** 不寫 `spec.md`、FR／AC、Gherkin，不談實作、不設計資料表——這一步只問、只記，記在
`interview-log.md` 這份流水帳。**不自己填答案**：`spec` 之後寫的每一條 FR 與 AC 都要指回這裡——`## 原文` 的某一段，
或某一題已答的紅卡（`spec` 照抄進 `spec.md`）；所以這裡記下的每一題都要有答案原話與 `**誰答的**`。

## 使用時機

- 有一個想法、或一份別人寫的 PRD／ticket／會議紀錄，要收進流程問到完整——找出原文沒寫、但整份預設成立的假設
- 拿到一段需求或一則 story，但講得太抽象，不知道要做到什麼程度
- `spec` 寫規格時開了待答題、把 `spec.md` 改回 `澄清中`，要把那些題問掉
- 手上有一疊待答的題，想知道哪些能當場解決、哪些必須去問別人
- 懷疑需求有沒想到的邊界情況

## Skill Boundaries

| 情況 | 改用 |
| --- | --- |
| 只是要把一則太大的 story 切開 | `story-splitting`；本 skill 只寫粗切 |
| 要把答案寫成 FR／AC | `spec`，由使用者叫 |
| 要判就緒、攤四色卡 | `spec`，它寫完規則後委派 `example-mapping` |
| 要寫 seam、API、schema、測試層級 | `plan`（`spec.md` 已對焦、`.feature` 寫好之後） |

產出是 `interview-log.md`，**不是** `spec.md`、FR／AC、`plan.md`、`.feature`、程式碼或資料模型。

## 參考檔案

- `references/opening.md` — 第 0 件事（建檔）的做法、四題的表、粗切樣板。**建檔時讀**
- `references/interview-log-format.md` — `interview-log.md` 的五節、一題的欄位、狀態值。**寫檔之前讀**
- `examples/interview-log.md` — 一份收斂的紀錄；`../spec/examples/minimal-spec.md` 是 `spec` 照它寫成的規格
- `references/persona-definition.md` — 角色五欄的判準、寫法與範例。識別角色、或冒出新角色時讀
- `references/technical-probes.md` — 五個技術面向各問什麼、自己查還是問人。前沿碰到技術面向時讀
- `references/stand-in-mode.md` — 需求方不在場時怎麼代演。只在代演時讀
- `scripts/status.py` — 從紀錄的 `## 問答` 算紅卡與面向覆蓋。收尾核對時跑

## 前置確認（Ask user）

**唯一必要的輸入是需求本身**：一段描述、一份文件的內容或路徑，或已經存在的
`specs/ongoing/<date>-<feature>/interview-log.md`。沒有紀錄、或它還沒有粗切 story，就先建
（開場的第 0 件事，`references/opening.md`）；建好的，它要有 `## 原文` 一節、粗切至少一則，
而且建檔那場 Session 有 `**需求方確認建檔**` 一行——沒有就是他還沒點頭，
第 0 件事從收尾接著做。旁邊的 `spec.md` 已經 `待對焦`／`已對焦` 的不跑：那是 `spec` 的事，除非使用者要喚醒或改它（見下）。

NEVER: 還沒把原文逐字寫進 `## 原文` 就開始問。問出來的答案沒有地方寫、`← Q-<n>` 沒有
題可以指、`← PRD §x` 沒有話可以指，整場訪談會留在對話裡然後消失。

產物路徑不必問，就是那份 `interview-log.md`；建檔時只問 feature 的 slug。

### 喚醒——要改的 feature 已經在 `specs/sleeping/`

這次的需求是要**改一個做完的 feature 的 FR／AC** 時，不開新目錄——停下來，告訴使用者先跑 `/spec` 喚醒它：
搬回 `specs/ongoing/`、把 `spec.md` 改回 `澄清中` 是 `spec` 的事（`../spec/references/wake-up.md`）。喚醒之後
目錄回到 `specs/ongoing/`、`interview-log.md` 還在，照〈續跑〉追加一場 `### <日期> · 喚醒` Session 再問。是**新的
story**、只是碰到同一批程式碼時，照常建檔。

### 代演模式——需求方不在場時

benchmark 實跑或離線試跑、沒有人可以答時，可以**代演**需求方與開發者，但每一個代演的
答案都要在檔案上看得出來（`**誰答的**` 寫 `代演（需求方）`／`代演（開發者）`）。登記方式、
推到 `已對焦` 的條件、實跑報告 → `references/stand-in-mode.md`。

## 流程

| 步驟 | 做什麼 | 要問使用者嗎 |
| --- | --- | --- |
| 0 | 建檔：原文逐字、粗切 story、最多四題、改到需求方點頭（只做一次，見〈開場〉） | 要，給需求方看整份 |
| 1 | 開場其餘：掃原文找隱含假設、補核心關係人、識別角色——問出來的都開成『待答』題；寫一句開場假設與信心 | — |
| 2 | 算前沿，過〈值不值得問〉；能自己查的事實派 sub-agent 查；照影響排序 | — |
| 3 | 問影響最大的那一題：上下文、一句問題、猜測的答案與理由（〈一題長什麼樣〉） | 要，一次一題 |
| 4 | 答案回來：記下、確認夠具體、更新信心、看停下來的訊號 → 回到 2 | — |
| 5 | 停的條件成立：收尾核對 → 意圖陳述 → 需求方說 yes → 結束方式，STOP（〈結束〉） | 要 |

續跑時開場已經做過，從步驟 2 接著做；`spec` 開的待答題先問。不論停在哪一步，結束方式
四選一（收斂／阻塞／零進展／喊停）寫在紀錄的 `## Remaining Open Items`（見〈完成後〉）。

### 續跑

| 呼叫方式 | 範圍 |
| --- | --- |
| `discovery` | **預設：`specs/ongoing/` 底下所有還沒問完的 feature**——紀錄的結束方式不是 `收斂` 的，加上 `spec.md` 被 `spec` 改回 `澄清中` 的 |
| `discovery <feature>` | 只跑指定的那一個 |

**不要問對方要跑哪一個。** 預設全部，想限定的人自己會帶參數——多問一次等於把
決定推回去，而多數時候答案就是「都繼續」。

**開場做過沒有，看紀錄的 `## 問答` 有沒有任何一題的 `**面向**` 不是 `—`。** 第 0 件事只會
記 `面向` 為 `—` 的題（它的四題與需求方自己列的開放問題），前沿一算就會冒出帶
面向的題——一題都沒有就是開場還沒跑。有，就只讀不重跑，並且**用它重建設計樹**：『已答』的每一題是一個已定案的
決定，『待答』是還開著的分支，『n/a』『失效』是走過但判定不適用、或被取代的。前沿從這幾種題算得出來。

**補問的題先問。** `spec`（與它委派的診斷 skill）寫規格時發現的洞，開在 **`spec.md`** 的 `## Open Questions`
（`待答`、`**來自**：補問 —「…」`），再把它改回 `澄清中`。續跑時**只讀** `spec.md` 的待答題，紀錄裡還沒有的題號
在 `## 問答` 追加成**同號**的一題（`**來自**`、`**該問誰**` 原樣抄），先問這些，再照常算前沿；`spec` 再跑時讀紀錄修補 `spec.md`。

MUST NOT: 寫 `spec.md`——連補問題的狀態、答案欄也不改。它只有 `spec` 一個寫入者；答案靠紀錄傳過去。

IMPORTANT: 重問一題已經答過的，比漏問一題更傷信任——它證明你沒有讀既有產物。開題前先比對：
同一件事若已經被某一題的標題或 `**來自**` 逐字引過，不論那題待答還是已答，都不再開。新題號接兩份檔最大的號。

換 feature 時明講「現在開始 X」，並在每一題答完回報還剩幾題待答。跑多個 feature 時，
**跨 feature 的共用規則會浮現**——那是一次跑完全部的主要收穫，單獨跑一個看不到。

### 開場：只做一次的幾件事

#### 0. 建檔（`interview-log.md` 不存在、或還沒有粗切 story 時）

原文逐字進 `## 原文`、沿使用者目標粗切 story（`US-<n> · <slug>` 加「身為…」一句，記在建檔那場 Session）、背景／角色／目標／範圍原文
沒講的最多問四題（一次一題，答案記成 `面向` 為 `—` 的 `Q-<n>`）、需求方自己列的開放問題開成紅卡
——然後**把整份給需求方看一遍，改到他說「這是我的意思」**，點頭記成
那場 Session 的 `**需求方確認建檔**` 一行。這是自己的一個回合：他點頭之前不掃描、
不算前沿；續跑時沒有那一行就回到收尾。做法、四題的表、粗切的樣板 →
`references/opening.md`；檔案格式 → `references/interview-log-format.md`。

MUST NOT: 在這一件事裡寫 FR、AC、或任何規則。原文沒有規則；寫了就是編的。

#### 開場假設與信心

點頭之後、問第一題之前，在對話裡寫一句**你目前以為他要什麼**與**信心**（0–100%）；低於七成時接著寫
還缺什麼：「我目前的理解：<一句>。信心 40%——還不知道續借要不要擋逾期的人、休館日怎麼算。」之後每答完
一題就更新那個數字，讓需求方看得到問答在收斂。信心是判斷，不寫進檔案——進度是 `status.py` 算的。

#### 掃原文找隱含假設

第 0 件事是書記，收原文的時候不質疑。這一步對 `## 原文` 逐句質疑，問出來的題追加進
`## 問答`，`**面向**` 填 `—`（它們不屬於十六個面向）。

MUST: 原文裡標題叫「假設」、或語氣像既定事實的數字、門檻、SLA，**每一條都當成沒問過**
——它是未驗證的斷言，不是前提。每一條開一題進『待答』，`**上下文**` 註明是原文哪一段
（`§n`）。`spec` 寫 `## Assumptions / Constraints` 時，問過的引 `← Q-<n>`，
沒問過的才引 `← PRD §n`。

**找隱含假設要靠機械掃描，不是靠讀。** 假設對寫的人而言是常識，常識不會被
寫下來。對 `## 原文` 裡的每一個元素問同一句話：

| 掃什麼 | 問什麼 | 逮到的是 |
| --- | --- | --- |
| 每個**名詞** | 這是誰定義的？兩個人會不會算出不同的數？ | 沒定義的業務術語 |
| 每個**數字** | 這個數字從哪來？換成別的會怎樣？ | 拍腦袋的門檻與 SLA |
| 每個**「自動」「即時」「應該」** | 誰做？什麼時候做？沒做成怎麼辦？ | 沒列出來的 actor（多半是系統自己） |
| 每個**成功指標** | 這個指標要成立，哪些行為必須存在？PRD 有寫嗎？ | 指標與功能之間缺的那一段 |
| 每個**排除項** | 排除 A 是不是隱含要做 B？ | 被排除項推出來的隱藏需求 |

#### 補核心關係人

第 0 件事登記了需求方與他點名的人。這一步每冒出一個新的受訪者就在
這一場 Session 的核心關係人表補一列，三欄 `關係人／負責什麼／決策權`。
『待答』題的 `**該問誰**` 只能指向紀錄裡登記過的人——指到表外就補一列，不要當筆誤略過。

**`決策權` 這一格只有這裡寫得出來。** `spec` 不訪談，把這張表原樣抄進 `spec.md`、不增列也不改寫；這裡沒登記，下游就分不出
哪些答案是定案、哪些只是提案。

#### 識別角色

規則的敘述（EARS 的 `When <trigger>`）常常以角色當主詞，角色名稱不統一，
同一題會被問兩次、同一條規則會被記成兩種主詞，所以在深度追問前先定下來。

MUST: 每個角色問**是誰**／**怎麼取得這個身分**／**跟誰容易混**／**他要什麼**／
**現在什麼讓他痛**，每個角色一題、五欄的答案原話記在那一題；最後兩項答不出來就記
「（無資料）」，不要編。`spec` 從這些題寫 `## Personas`。判準、寫法與
範例、別漏掉哪些角色 → `references/persona-definition.md`。

## 前沿怎麼算

### 設計樹

每個已定案的決定會岔出依賴它的下一批決定。**前沿 ＝ 所有前提已經定案的決定。**

判準只有一句：**這題的答案，會不會因為另一題還沒答而改變？** 會，它不在前沿上，等那一題答了再說。

前沿是**算**出來的，不是猜哪些題該先問。範圍題之所以先問，不是因為有人規定，是因為
其他幾乎所有題的前提都掛在它身上。前沿上的題**照影響排序**：答案會改動最多規則、擋住最多題的先問。

MUST NOT: 因為某題「感覺比較重要」就問一題不在前沿上的。重要決定的是前沿**裡**的順序；
前提沒定案的題問出口，拿到的是一個建立在還沒問到的答案上的回答。

### 十六個面向是前沿的檢查表

11 個業務面向（下面兩張表）與 5 個技術面向（seam、模組邊界、介面與型別契約、
排序契約／決定性、既有資產／測試慣例）是**每次算前沿時的檢查表**，也是收尾時判斷還有什麼沒問的覆蓋表：

> 對每一個**已經定案**的決定問——這 16 個面向裡，有哪個還沒對它問過？

問得出來的就是前沿的候選題。技術面向多一條：**能自己查的先查**（見下一節），
每個面向各自問什麼 → `references/technical-probes.md`。

**追問清單**（找模糊點用，不是待辦清單）

| 面向 | 問法 |
| --- | --- |
| 空與零 | 沒有資料、空字串、零筆、第一次使用時？ |
| 邊界 | 剛好等於上限？超過 1 個單位？ |
| 重複 | 同一個動作做兩次？重送？**同一個人把整個流程再走一遍**（出去再進來、退了再買）？ |
| 時序 | 兩件事同時發生？順序顛倒？ |
| 權限 | 換一個角色來做？沒登入？ |
| 失敗 | 外部系統掛掉？逾時？做到一半斷線？**每一種身分憑證各自遺失、讀不到、不在名單時**？ |
| 時間 | 跨日、跨時區、日光節約？過期的定義？ |
| 規模 | 一次一萬筆？ |

**非功能面向**（行為級的那些）

| 面向 | 問法 |
| --- | --- |
| 降級 | 依賴不可用時**降級成什麼**？還是整個失敗？ |
| 時限 | 多久算太久？超過了怎麼辦——等、失敗、還是給舊資料？ |
| 可觀測 | 這件事出錯時怎麼會知道？留下什麼才查得出原因？ |

這三個跟上表的「失敗」不重複：**失敗問的是會不會壞，降級問的是壞了之後呢。**
兩者是不同的規則，只問前者的結果是規格寫了一半——寫了偵測，沒寫善後。
舉不出例子的產品級品質屬性（「所有操作三秒內」）由技術面向那五個接手，
不會在這裡重複。

清單是起點不是全部——這個領域有什麼特有的失敗模式，一併找。

面向名稱與順序是 `scripts/status.py` 的 `DIMS` 與
`references/technical-probes.md` 的共用契約，**不得增減或改名**。每一題的
`**面向**` 照樣填——`status.py` 的追問覆蓋率完全靠那一格，而它是這個 repo 裡
唯一看得出「有沒有真的問過邊界」的東西。

### 值不值得問

MUST: 問出口之前先過這一關——**這題的不同答案，會不會導致不同的規則？**

不會，就不要問。這條篩掉的通常是最多的：十六個面向對每個已定案的決定掃一遍，
掃出來的候選有一大半的答案其實不影響任何行為。**問題少而準，比多而全有用得多**
——五個已定案的決定乘十六個面向是八十題，一題一題問下去，需求方在第十題就開始答「都可以」。

**這一關刪題，不是把題排到後面。**〈設計樹〉答的是「什麼時候問」，判準是前提
定沒定案；這一關答的是「問不問」。

篩掉的不會消失：跟〈答不出來：三堆〉的「這題不該問」走同一條路，在 `## 問答` 記一題、狀態 `n/a`、
`**收斂結果**` 寫清楚為什麼不用問。不記，收尾核對時那個面向會找不到任何一題。

### 能自己查的事實不准問使用者

MUST: 問題需要的**事實**若在環境裡查得到——既有測試怎麼寫、某個模組的介面
長怎樣、有沒有現成的 seam——**派 sub-agent 去查**，不要問使用者。
哪些事實查得到、哪些是只有人能給的決定 → `references/technical-probes.md`
每一節的 **`自己查還是問人`** 那一段。

MUST NOT: 因為 sub-agent 還在跑就停下來。**一個進行中的探查是一個未定案的前提**
——只有依賴它的問題要等，**前沿其餘的照問**。

**決定是使用者的，事實是你的。** 把事實問題丟回去，等於要對方做你做得到的功課，
而且他的答案未必比環境裡的真相準。

## 一題長什麼樣

MUST: **一則訊息只問一題。** 等答案回來、記好、重算前沿，再問下一題。

```
**Q-7 · 到期日碰上休館**　（信心 55%）

§3 說借期兩週、每週一與國定假日休館；Q-4 答了到期日要寫在借書單上。
兩週後那天若是休館日，讀者那天還不了書。

❓ 到期日剛好是休館日，算不算逾期？

➡️ 我猜：不算，順延到下一個開館日——讀者那天沒地方還書，算他逾期等於罰他館方的休假。
```

| 部分 | 寫什麼 |
| --- | --- |
| 上下文 | 判斷這題需要的東西：原文哪一段、前面哪一題的答案、sub-agent 查到的事實。對方不必翻檔就答得出來 |
| 問題 | 一句。兩個問號就是兩題 |
| 猜測 | 你以為的答案與**為什麼**。對方只要判斷「對不對」，不必從零想 |

**猜測是逃生口，不是裝飾。** 一個沒有猜測的問題把全部認知負擔丟回去；一個
有猜測的問題只要求對方判斷「對不對」。純業務價值的取捨（要比較週與週還是同一動作的進步）沒有慣例可循，
猜的時候明說「這是我的偏好，你的判斷勝過我」。

MUST: **沒有站得住的猜測時，猜測欄寫「這題我不建議猜——要去問 <誰>」**，
`<誰>` 指向紀錄裡核心關係人表的人。編一個聽起來合理的猜測，比承認不知道更糟
——對方多半會直接接受，而那個答案從此看起來像是問過的。

### 常見藉口

| 藉口 | 實情 |
| --- | --- |
| 「這幾題彼此沒依賴，一起問比較快」 | 一則訊息三題以上就是批次：對方挑好答的答，難的那題被跳過也看不出來 |
| 「他說『你決定就好』，那就照我的猜測記」 | 那不是答案。給兩個具體選項重問一次（「順延到下一個開館日，還是當天就算逾期？」） |
| 「答案聽起來很明確，先記下再說」 | 照著做事才會發現缺條件。當場追一題，見〈確認答案夠具體〉 |
| 「這個我查得到，但問一下比較保險」 | 能查的事實不准問；他的記憶未必比環境裡的真相準 |
| 「已經問很多題了，剩下的 spec 會自己補」 | `spec` 不准補——沒問到的會變成它開的補問題，又退回來 |

## 答案回來之後

### 記錄：四件事一起做

MUST: 一題的答案回來，以下四件事跟著發生，缺一個就是不一致狀態：

| # | 動作 |
| --- | --- |
| 1 | 答定的，那一題的 `**狀態**` `待答` → `已答`；追加**答案原話**那一行、`**誰答的**` 與 `**收斂結果**` |
| 2 | 答案帶出具體例子的（「9/26 借出、10/10 休館，到期日是 10/11」），例子原樣記進那一題——`spec` 寫 AC 時要找得到它，不能從一句結論重建 |
| 3 | 若這個答案消掉了其他還沒問的問題，說出來，那些題狀態改 `失效`、收斂結果寫被哪一題消掉 |
| 4 | 對方對你的猜測回「不是」時，`**猜測**` 照留，正確答案追加在下面（決策史） |

欄位 → `references/interview-log-format.md`。答案一律追加，不覆寫前一行。

**當場記，不要事後補。** 剛答完那一刻你還記得對方的原話與例子；隔了二十題再回來寫，
會寫成「大致上是這個意思」的版本，而 `spec` 會把那個版本當成定案寫成規則。澄清很少
一次做完，**停在任何一題，`interview-log.md` 都該是完整可用的**——session 斷了，下一次從它接著問。

MUST NOT: 在這一步寫 FR、AC，或把答案「先整理成規則草稿」放進任何檔案。規則只在
`spec` 寫，那裡才有 `check_spec.py` 第 14 項機械地查每一條的來源。

### 想要的，還是覺得應該要的

答案裡出現流行詞、「業界標準的做法」「我應該要…吧」，多半是他覺得**應該**要的，不是他**想**要的。
追一句：「如果不必跟任何人交代理由，你實際上想要的是什麼？」兩個答案不同時，兩個都記進那一題，
問他規則要照哪一個；不要自己挑。

### 答不出來：三堆

對方答「不知道」或要跳過時，那一題歸進三堆之一，追加一行 `**堆**` 記下是哪一堆、為什麼：

| 堆 | 判準 | 怎麼處理 |
| --- | --- | --- |
| **可解，之後再問** | 他答得出來，只是現在不想定 | 留 `待答`；下一次算前沿照樣在 |
| **阻塞** | 要另一個角色才答得出來 | 留 `待答`，寫 `**該問誰**`（指向核心關係人表）與要問什麼 |
| **失效** | 前面的答案讓它不再成立，或它**不該問**（確認不影響任何規則） | 狀態改 `失效`（被取代）或 `n/a`（不該問），收斂結果寫取代它的那題、或為什麼不用問 |

IMPORTANT: 阻塞的題目**不要換句話說再問一次**。對方答不出「業界怎麼算」不是
因為問法不好，是因為他不知道。重問只會換到一個猜測，而猜測被記成答案之後就沒有
人會回頭質疑它。

只記「跳過」不記是哪一堆，紅卡就會變成一堆分不出輕重的待辦——而那
正是讓人一個都不想動的狀態。

### 確認答案夠具體

MUST: 每一題答完就檢查答案是不是還停在抽象層次，不要累積到最後。

一個答案在對話裡聽起來很明確，一旦要照著做事就會發現它缺條件——等全部答完
才發現，那些漏洞會一次湧出來，而且上下文已經冷了。

**答案要具體、含實際資料，不要只是換句話說：**

- ✗「一個無效的使用者」—— 這只是換句話說
- ✓「一個 token 在 3 秒前過期的使用者」

答案不夠具體，回頭追問，不要就這樣記下模糊的版本——**模糊的答案比誠實的
「待答」更危險**，它看起來已經解決了。在前沿上它還更貴：一個糊的答案照樣被當成
定案，掛在它底下的一整批題會被算進前沿，而那些題的前提其實還是糊的。

「都可以」「你決定」「聽起來不錯」不是答案：給兩個具體選項再問一次。連續幾題都這樣回，是疲勞不是共識——停下來問他要不要喊停。

### 停下來的訊號

以下訊號代表問不動了，出現就停下來講，不要繼續往下問——結束方式怎麼寫見〈完成後〉：

| 訊號 | 意義 | 結束方式 |
| --- | --- | --- |
| **連續兩題被跳過** | 可能問錯層次，或整組問題超出對方的知識範圍。停下來確認 | 阻塞 |
| 剩下的都在阻塞那一堆 | 前沿非空，但沒有一題是在場的人答得出來的 | 阻塞 |
| 問了十來題但前沿不縮 | 先確認範圍有沒有抓錯：**沒抓錯**——這個 feature 本來就大，不是切小它，繼續問完，多大交給 SPEC 之後決定；**抓錯了**——**開一題新的，重問那條邊界**，記進『待答』，照樣算前沿 | 零進展 |
| **答案沒有改變任何行為** | 問出來的都不影響系統怎麼做。問題選錯了，回頭看〈值不值得問〉那一關 | 零進展 |

零進展時先判斷是哪一種成因，再決定下一步：**問錯層次**（在問實作細節，真正沒定的是上位目的——往回問一層）、
**問題其實是同一個**（幾張紅卡是同一個未決定的不同面向——合併成一題）、**他真的不知道**（全部轉阻塞，列出要問誰）、
**範圍**（上表第三列）。第三種最常見，也最常被誤判成前兩種而繼續磨。

**沒有「把答案收回去」這個動作。** `## 問答` 只追加：『已答』的一題
記的是**當時問了什麼、答了什麼**，那件事確實發生過。定錯的邊界靠**新開一題**取代，
新那一題寫 `**來自**：取代 Q-<舊>`、舊那一題狀態改 `失效`、追加收斂結果寫被哪一題取代；`spec` 再跑時把引用舊題的規則
改引新題。`Q-<n>` 全域唯一且不重排，整份 `## 問答` 因此讀得出是哪一題改了主意。

這不牴觸「重問一題已經答過的，比漏問一題更傷信任」——那條講的是**沒讀既有產物**就
重問。這裡是帶著理由回去重問，理由寫進新那一題的 `**上下文**`，對方看得出你為什麼再問一次。

## 結束

**停的條件兩個都要成立：**

1. **猜得中**：你接下來會問的三題，你都猜得中他會怎麼答——再問只是確認，不會改任何規則。前沿空了是它的強形式
2. **收尾核對過**（下面四項）——第一個憑感覺，這個是它的驗收

### 收尾核對

1. **核對覆蓋**：跑 `python3 scripts/status.py <專案根>`。十一個業務面向每一個都至少
   出現在某一題的 `**面向**`——包含標 `n/a`、`失效` 的。技術那五個一樣各印一欄，但這一關
   不擋它們（理由見 `references/technical-probes.md` 開頭）
2. **核對角色**：粗切的每則 story 的 `身為` 都有一題問過那個角色的五欄
3. **核對優先級**：story 有兩則以上時，有一題問過「哪則最重要、只做它能不能先上線」——
   答案是每則的 P1／P2／P3 與為什麼。沒問過就問這一題。`spec` 照它排 story 的優先級，
   `plan` 與 `task-breakdown` 照它排切片順序；沒有這一題，優先級只能由寫規格的人自己排
4. **稽核分類是否窮盡**（見下）

核對不能跳過——它是「面向要嘛問過要嘛標 n/a」那條規則的驗收。若某個面向連
一題都沒有，代表它根本沒被想過，**先補一題**再往下走。

### 稽核分類是否窮盡

MUST: 問答裡浮現的每一張**列舉型的表**（型別、狀態、角色、單位，**以及實體本身的種類**——車種、票種、卡種）拿出來問一次：
**這個領域裡有沒有一種真實存在的東西，這張表放不進去？**

追問清單的十一個面向問的都是**已知那件事的極端值**——空、邊界、重複、時序。問不到
**漏掉一整類資料**，因為漏掉的那類從來沒出現在對話裡，沒有極端值可問。

實測過一次：健身 App 的動作型別表有六種，全部以「次數」計量，於是棒式（60 秒，
沒有次數）無處可放，被迫和跑步機歸成同一類。三輪澄清都沒問到，是抽完規則後回頭
對照才發現的。

找到放不進去的東西，就開一題新的，記進 `## 問答`——不要自己塞進最接近的那一格。

### 意圖陳述：要他明說 yes

核對過之後，回寫一段意圖陳述，開成一題 `Q-<n>`「意圖陳述對不對」（`面向` `—`），六行寫在 `## Confirmed Decisions` 的 `### 意圖陳述（Q-<n>）`：

```markdown
- **Outcome**：做成之後的樣子
- **User**：為誰做（`P-<n>`）
- **Why now**：為什麼現在做
- **Success**：怎麼知道做成了
- **Constraint**：做不到、不准的
- **Out of scope**：明確不做的
```

MUST: 每一行都要指得回已答的題或 `## 原文`；寫不出來的那一行就是還沒問到——回去問，不要補。
他回「對」才把那題記成 `已答`（答案原話照記）；他改了哪一行，改的就是一題新答案，照〈記錄〉記下，
必要時接著問。`spec` 寫 `## Goals / Non-Goals` 與 `## Success Metrics` 時可以引這一題。

然後重寫 `## Confirmed Decisions`（意圖陳述與已拍板的決定，每條指回 `Q-<n>` 或 `§n`）與
`## Remaining Open Items`（`**結束方式**`：`收斂`）。**STOP**——這一輪不做任何下游的事。

### 決策史住在紀錄的 `## 問答`

`spec` 把答案寫成規則之後，**為什麼**仍留在規則的 `← Q-<n>` 指向的那一題裡：問了誰、
答案怎麼來的、被推翻過的猜測。下次改動第一個會問的問題往往是「當初為什麼不選
第二個選項」，答案只在那裡找得到。紀錄不是規則的定案來源——規則以 `spec.md` 的 FR／AC 為準；
`spec.md` 的 `## Open Questions` 是從紀錄整理的版本，兩處對不上時以紀錄的原話為準。

## 產物

`specs/ongoing/<date>-<feature>/interview-log.md` 的五節（`## 原文`、`## Session`、`## 問答`、`## Confirmed Decisions`、
`## Remaining Open Items`），格式 → `references/interview-log-format.md`。`spec.md` 由 `spec` 讀它寫。

MUST NOT: 改寫 `## 原文`。要補充就開一題；原文被改寫，每個 `← PRD §x` 從此指向
一句沒人說過的話，而且不會報錯。

MUST NOT: 改寫或刪掉 `## Session`、`## 問答` 已經記下的行——只追加，唯一可改的是一題的 `**狀態**`；
也不寫 `spec.md`、FR／AC、`plan.md` 或 `.feature`。紀錄是證據，規則是 `spec` 照它寫的，seam、API、schema 是 `plan` 的事。

MUST NOT: 另存一份進度儀表板。進度是**算出來的**——
`scripts/status.py` 從 `## 問答` 直接數；問答史就在那一節。

### 產物隔離

文件型產物**全部住在 `specs/`**，一個目錄裝完。專案的其他地方不會多出東西。

| 規則 | 強度 |
| --- | --- |
| 只寫入 `specs/` 底下 | `MUST` |
| 不修改專案既有的任何檔案 | `MUST` |

本 skill 只寫 `specs/ongoing/<date>-<feature>/interview-log.md`，不碰 `spec.md` 與 `docs/`。

## 完成後

在 `## Remaining Open Items` 的 `**結束方式**` 填上這一次怎麼停的，四選一（`spec.md` 若在，一個字都不動）：

| 結束方式 | 什麼情況、要做什麼 |
| --- | --- |
| **收斂** | 停的條件成立、意圖陳述得到 yes。告訴使用者下一步是 `/spec`——本 skill 不叫它 |
| **阻塞** | 卡在等外部答案，對應的題寫清楚卡在誰身上、等什麼；`## Remaining Open Items` 的表列出「誰要回答什麼」 |
| **零進展** | 一直答不出新東西，說明判斷是哪一種成因、建議怎麼調整 |
| **喊停** | 使用者決定帶著還開著的問題往下走。`spec` 收這一種，還『待答』的題會在對應 story 的 `#### Q` 留指標；`阻塞`、`零進展` 它拒收 |

不要不講就往下跑——收斂以外的三種都代表還有洞。
