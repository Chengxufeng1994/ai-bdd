# CLARIFY 評分方案 — 個人待辦

**這份是答案卷。跑 eval 的 session 不可以讀到它。**

同一個情境兩份輸入，共用這一份評分方案：

| 輸入 | 測什麼 |
| --- | --- |
| [`input-brief.md`](./input-brief.md) | 需求裡**兩句直接打架的話**，看不看得出來 |
| [`input-prd.md`](./input-prd.md) | 面對**看起來已經完成**的輸入，敢不敢質疑它 |

兩份輸入檔是**純酬載**——沒有標題、沒有說明。任何「這是評估用的固定輸入」之類的
抬頭，本身就會告訴被測者它正在被評估。逐字餵，不要即興改寫。

怎麼跑一次 → [`../../README.md`](../../README.md)。

---

## 為什麼選這個題目

因為**模型見過太多次待辦 App**，它可以不問就答得出來——完成的劃掉、可以刪除、
可以排序。那些不是推理出來的，是訓練資料裡的。

CLARIFY 的核心主張是「問，而不是猜」，而**熟悉的領域正是最誘人去猜的地方**。所以
這個題目測的是最難的那一關：需求裡有幾個地方跟常見設計**不一樣**，背不出來，只能問。

一份靠先驗填完的產物，跟一份問出來的產物，在外觀上長得一樣——**除非題目裡藏著
跟預設相反的東西**。這份輸入藏了三個。

## 口語 brief 版：為什麼是這樣措辭

| 句子 | 表面上 | 實際上 |
| --- | --- | --- |
| 「有些是要做的事，有些只是想記著別忘記」 | 隨口補充 | **兩種不同的東西**：一種有「完成」狀態，一種沒有。系統要不要分？不分的話，「只是想記著」的那些永遠不會被打勾 |
| 「打勾之後就讓它自己消失」 | 一個已經決定的行為 | **「消失」是什麼**——隱藏？刪除？封存？隔天清？**還原得了嗎？** 這是全篇最像已定案、實際最空的一句 |
| 「我想知道我這個禮拜做了什麼」 | 一個附加的小願望 | **跟上一句直接矛盾**，而且只隔兩行 |
| 「手機用得比較多，但有時候在電腦前想到也會想記」 | 使用習慣 | 單機還是跨裝置同步？**這兩個是量級完全不同的專案** |
| 「大概每天記個五到十條吧」 | 規模資訊 | 唯一的軟化詞在這裡（「大概」「吧」）。而且三個月累積約六百條，**需求裡沒有人提搜尋** |
| 需求方＝使用者本人 | 看似最單純的情況 | 反而少了一層轉述——他講的是**他自己的習慣**，所以「他沒想到的」就真的沒有人會想到 |

## 模糊點

分三層，因為**它們被發現的時機不同**。

### 第一層 — Pass 1 就該問（答案改變切分方式）

1. 「要做的事」與「只是想記著的事」是不是同一種東西
2. **單機還是跨裝置同步**
3. 資料存在哪、換手機或重灌怎麼辦
4. 「這禮拜做了什麼」是一個功能，還是一句附帶的感想

### 第二層 — Pass 2 深度追問

5. **「消失」到底是什麼**：隱藏／刪除／封存／隔天清
6. 消失的還原得了嗎；打勾可不可以取消
7. 刪除跟完成是不是兩件事
8. 「只是想記著」的項目要不要有「打勾」這個動作
9. 有沒有截止日或提醒；過期的怎麼顯示
10. 排序：手動拖曳／新的在上／舊的在上／完成的沉底
11. 空清單長什麼樣（第一次打開、全部做完）
12. 一則很長的內容跟一句話，顯示方式一樣嗎
13. 內容重複的兩筆算不算重複
14. 累積六百條之後怎麼找到某一筆——**需求裡沒有人提搜尋**
15. 「這個禮拜」是週一到週日，還是最近七天

### 第三層 — 只有推導才會浮現

16. **「打勾就消失」與「想知道這禮拜做了什麼」直接矛盾。** 兩句話隔兩行，各自都
    合理。只讀不推的執行會**兩個都實作**，然後在寫場景時才發現週回顧沒有資料可讀
17. **需求方的解法解決不了他自己的問題。** 他要消掉「畫面很亂」，手段是「打勾就
    消失」；但他自己說了有些項目「只是想記著別忘記」——**那些永遠不會被打勾，
    所以永遠不會消失，畫面還是會亂。** 這一條不會在提問時出現，只會在**把兩條
    規則放在一起**時撞出來
18. **單機的代價他沒想過。** 他每天都在用、記的是他怕忘記的事，而「換手機資料就
    沒了」是遲早會發生的事。第 2 題答「單機」的話，這個後果要被講出來

## 及格標準

**必要（沒問到就算失敗）**：第 16 與第 2 項。

理由：它們是唯二**改變交付物本體**的。第 16 項不問，會交付兩個互相抵銷的功能；
第 2 項不問，範圍可能差好幾倍（單機的本地儲存 vs 帳號、同步、衝突解決）。

第 16 項特別能鑑別，因為**矛盾就寫在輸入裡、字面上就看得到**——需要的不是領域
知識，是**把需求方講的兩句話並排讀**。抓不到它，代表這次執行是在逐句處理需求，
不是在理解它。

**進階（區分「夠用」與「好」）**：第 17 項。

它比第 16 項難一層：第 16 項是兩句話打架，第 17 項是**解法與目的打架**，而目的
（畫面不要亂）只在半句話裡出現過。抓到它的執行，是真的在檢查「這個做法會不會
達成他要的」，而不只是在收集規則。

**鏈的完整性**：第 14 項。

搜尋。需求裡一個字都沒提，而且**在前三個月不會痛**。它衡量的是這次執行有沒有
沿著時間往前推——「這個東西用半年之後長什麼樣」。

## 怎麼比較兩次執行

| 觀察項 | 好的樣子 |
| --- | --- |
| 兩句矛盾 | 有沒有被指名為矛盾，而不是各自記成一條需求 |
| 「消失」 | 有沒有追問它是哪一種，而不是預設成軟刪除 |
| 兩種項目 | 「要做的事」與「想記著的事」有沒有被當成兩種東西處理 |
| 先驗填空 | 有沒有出現需求方沒講、也沒問過的東西（子任務、標籤、優先級、提醒）——**那是背出來的，不是問出來的** |
| 單機／同步 | 有沒有把它當成範圍問題問，而不是當成技術細節略過 |
| 往前推 | 有沒有想到「半年後六百條」這種與時間有關的後果 |
| 成功指標 | 有沒有發現需求方要的是「不漏掉事情」，而不是「每天記幾筆」 |
| 紅卡 | 需求方是使用者本人，**沒有人可以轉問**——答不出來的題要怎麼處理 |

## PRD 版：這一版多了哪些陷阱

口語版的三個陷阱都保留，但改成看起來已經決定的樣子：

| 陷阱 | 為什麼有效 |
| --- | --- |
| **`FR-3` 寫「自動從主畫面隱藏」** | 把「消失」定死成「隱藏」，看起來解決了第 5 項。但它沒說隱藏到哪、找不找得回來、`FR-6` 的刪除跟它差在哪 |
| **`FR-3` 與 `FR-4` 並列** | 矛盾還在，但被編號拆成兩條獨立需求。**編號本身就是一種掩護**——兩條各自成立的 FR 看起來不像在打架 |
| **「狀態：已核准」** | 權威訊號。測會不會因為文件看起來定案就降低追問強度 |
| **第 8 節「假設」直接寫死「單一裝置」** | 把第 2 項從「沒問」變成「已決定」。但那是**假設**不是**決定**——沒有人驗證過使用者接不接受換手機就沒了 |
| **第 6 節「不在本次範圍」** | 排除的四項（協作、看板、行事曆、自然語言）全是不相干的東西。**搜尋、備份、資料遷移一個字都沒提**——真正的邊界一條都沒畫 |
| **第 7 節成功指標** | 全是參與度（日活、每日筆數、留存），沒有一條衡量「使用者有沒有真的少漏掉事情」。目標與指標脫節，但看起來很完整 |
| **`FR-1` 寫「單行文字」** | 悄悄砍掉了「有些只是想記著別忘記」那一類——備忘常常不是一行。這個限制沒有任何理由，但它讀起來像規格 |

## PRD 版：額外的觀察項

跑 PRD 版時，除了上面那 18 項再多看四個：

| 觀察項 | 好的樣子 |
| --- | --- |
| 對 `FR-3` 的態度 | 有沒有指出「隱藏」沒有定義隱藏到哪、跟 `FR-6` 的刪除差在哪 |
| 對 `FR-3` 與 `FR-4` 的態度 | 有沒有發現**編號把矛盾拆開了**，兩條並排讀仍然打架 |
| 對第 8 節的態度 | 有沒有指出「單一裝置」是假設不是決定，而且承重的假設不在這一節 |
| 對第 7 節的態度 | 有沒有問「這些指標衡量的是使用量，不是使用者有沒有少漏掉事情」 |

四項都沒發生，代表 skill 被文件的形式說服了——**那比在口語版漏問更嚴重**，因為
真實世界的需求多半以這種形式抵達。
